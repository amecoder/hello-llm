# 第12章 プロのように使う — 機能の選び方、積み上げ方、確認の仕方

> **一言まとめ**: 上手に使うために必要なのは、ボタンをたくさん知っていることだけではありません。**仕事に合った機能を選び、繰り返すことは積み上げておき、結果は仕事の重さに応じて確認する**力です。
> この章では、第1〜11章で身につけたGeminiの機能を、自分の仕事に合わせて**組み合わせる方法**を扱います。

この章では、新しい機能はほとんど扱いません。前の章で学んだGeminiの機能を、いつ、どう取り出して使うかがテーマです。

何を任せるかを判断する方法や、任せる前に答えを知っている仕事で試す方法のように、**どのAIにも通じるやり方**は、[ステップ1 第11章「プロのように使う」](../00-common/11-expert.md)にあります。先に読んでおくと、この章が楽になります。この章は、そのやり方をGeminiの機能とメニューに合わせて見ていきます。

## 仕事に合った機能を選ぶ

メニューを先に選ばないでください。いま目の前にある仕事がどんな形かを、先に見てください。そうすれば、使う機能は自然に決まります（[ステップ1 第11章「仕事の形から見る」](../00-common/11-expert.md#仕事の形から見る)）。

| こんな仕事なら | これを使う | くわしくは |
|---|---|---|
| 質問し、整え、一緒に考える | ふつうの会話 | [ステップ1](../00-common/) |
| むずかしく考える必要がある | モデルボタンで思考レベルを上げる | [第2章](02-screen-tour.md#モデルボタン-—-モデルと思考レベル) |
| 残したくない質問 | 一時チャット | [第2章](02-screen-tour.md#一時チャット-—-記録が残らない会話) |
| 文書や小さなアプリを一緒に直す | Canvas | [第4章](04-files-create.md#canvas-—-文書とアプリを一緒に直す) |
| 資料をたくさん集めてレポートにする | Deep Research | [第6章](06-search.md#deep-research-—-長い調査レポートを受け取る) |
| 1つのテーマの資料を長く集める | ノートブック | [第6章](06-search.md#ノートブック-—-資料と会話をテーマごとにまとめる) |
| 同じ頼みごとを何度もする | スキル | [第7章](07-skills-apps.md#スキル-—-よくあるお願いを保存しておく) |
| 自分のメールやファイルから探す | 連携アプリ | [第7章](07-skills-apps.md#連携アプリ-—-gmail・drive・カレンダーをgeminiで) |
| 複数の手順を経て成果物を受け取る | タスク（有料） | [第8章](08-tasks.md#タスク-—-チャットのかわりに仕事をまるごと任せる) |
| 決まった時に繰り返す | スケジュール | [第8章](08-tasks.md#決めた時間に自動で-—-スケジュール) |

この表は、前の章の内容を1か所にまとめたものです。

ほとんどは、一番上の行、ふつうの会話ひとつで十分です。下の行へ行くほど、使用量を多く使ったり（Deep Research・タスク）、自分の情報をより多く渡したり（連携アプリ・タスク）します。**本当に必要なときだけ、1行ずつ下りていきましょう。**

## 繰り返すことは積み上げておく

使っているうちに、同じことを繰り返し言うようになります。繰り返すことを一度書き留めておけば、次からはGeminiが知った状態で始まります。

入れる場所は4つです。最初からすべて使う必要はありません。下の順番で、必要になったら1つずつ加えてください。どんなときは型にするときではないかは、[ステップ1 第11章「繰り返すことは積み上げておく」](../00-common/11-expert.md#繰り返す仕事は積み重ねておく)にあります。

1. **すべての会話で同じ頼みごとをする** → 「Geminiへのリクエスト（Gemini 요청 사항）」に指示として書きます（[第5章](05-memory.md#指示-—-毎回言わなくて済むように)）。
2. **1つのテーマの資料を繰り返し取り出して見る** → その資料をノートブックにまとめます（[第6章](06-search.md#ノートブック-—-資料と会話をテーマごとにまとめる)）。
3. **同じ手順を毎回説明する** → その手順をスキルにします（[第7章](07-skills-apps.md#良いスキルの書き方)）。
4. **決まった時に同じ仕事をする** → スケジュールを設定します（[第8章](08-tasks.md#決めた時間に自動で-—-スケジュール)）。

指示とスキルがごちゃごちゃになったら、こう覚えてください。**指示は常に従うルールで、スキルは合う場面でだけ取り出して使う手順です。** Geminiは、スキルの名前と説明を見て、いま使うかどうかを判断します。[^write]

### 作ったスキルはオンとオフで比べる

作ったスキルは、同じ頼みごとを2回送って比べてみましょう。1回はスキルをオンにして、もう1回は「無効にする（비활성화）」でオフにして。[^skills] 比べて直すコツは、[ステップ1 第11章「作った型は試して直す」](../00-common/11-expert.md#作った型は試して直す)にあります。

比べるときは、自分に問いかけてみてください。

- スキルをオンにした回答のほうが、自分の望む形に近いか？
- スキルが必要ない質問にまで、割り込んでこなかったか？

割り込んでくるなら、スキルの説明に、**いつ使うか**をもっと狭く書いてください（[第7章](07-skills-apps.md#名前・説明・指示の書き方)）。

## 表と数字を任せる

表のファイルをアップロードすると、Geminiが分析してグラフを描いてくれます（[第4章](04-files-create.md#ファイルのアップロード)）。

```
添付した表は、過去3か月の町のお店の品目別の販売記録です。品目別の合計を大きい順に表にして、棒グラフを描いてください。
計算に使った方法も、1行ずつ書いてください。
```

最後の行のように、**計算方法も一緒に書かせると**、どこで間違ったかを見つけやすくなります。

数字の分析では、結果を信じてよいのかがいちばんの心配です。まず、**すでに計算してある過去の資料**で合わせてみてください。答えを知っている資料で合っていれば、新しい資料を任せるときも、もう少し信頼できます。方法と例は、[ステップ1 第11章「表と数字を任せる」](../00-common/11-expert.md#表と数字を任せる)にあります。
大事な計算は、スプレッドシートや手で、もう一度確認してください。表は「Sheetsにエクスポート（Sheets로 내보내기）」で移せば、すぐに計算し直して確かめられます（[第3章](03-chats.md#ほかのアプリにエクスポートする)）。

## 仕事の重さに応じて確認する

すべての回答を、同じ程度に確認する必要はありません。**間違ったときに失うものが大きいほど**、より念入りに見ます（[ステップ1 第11章「仕事の重さに応じて確認する」](../00-common/11-expert.md#仕事の重さに応じて確認する)）。

| 仕事の重さ | 例 | こう確認する |
|---|---|---|
| 軽い | 夕食のメニューのおすすめ | 読んでみて、おかしければ見送る |
| 中くらい | 会の告知文 | 日付・場所・金額だけを原本と照らし合わせる |
| 重い | 契約・健康・お金 | 出典を開いて見て、専門家に確認する |

このガイドで学んだ確認のためのツールを、もう一度まとめると次のとおりです。

- 回答の下の**「出典」**を開いて、元の文章と照らし合わせます（[第6章](06-search.md#回答の根拠を確認する)）。
- 連携したアプリの回答は、**元のメールやファイル**を開いて見ます（[第7章](07-skills-apps.md#上手な聞き方)）。
- タスクは、**許可を求める画面**を念入りに読み、動いている様子を見守ります（[第8章](08-tasks.md#任せる前に-—-安全のルール)）。
- 医療・法律・金融の判断は、Geminiに任せません（[第9章](09-privacy.md#やってはいけないこと、信じてはいけないこと)）。

## 実際にやってみよう

1. 今週にした仕事を3つ思い浮かべ、上の「仕事に合った機能を選ぶ」の表で、それぞれがどの行に当たるかを選んでみる。
2. 過去1週間でGeminiに2回以上した頼みごとを探し、指示に入れるか、スキルにするかを決めてみる。
3. 第7章で作ったスキルをオンにしたまま1回、オフにしたまま1回、同じ頼みごとを送って、結果を比べる。
4. すでに合計を知っている家計簿の表をアップロードして合計を計算し直させ、自分が知っている値と同じか見る。

**続きの課題**（[読書会の準備](../00-common/practice-kit.md)）: 課題の帳簿ファイルをアップロードして、会費の合計を計算させる。課題の案内に書かれた合計と同じか確認し、違っていたら、Geminiが書いた計算方法のどこが間違っているかを探してみる。

## まとめ

- メニューより、仕事の形を先に見る。ほとんどはふつうの会話で足り、必要なときだけDeep Researchやタスクのような機能へ下りていく。
- 繰り返すことは、指示 → ノートブック → スキル → スケジュールの順に、必要になったら1つずつ積み上げる。
- 指示は常に従うルール、スキルは合う場面にだけ使う手順だ。作ったスキルは、オンとオフで比べる。
- 表と数字は、計算方法も一緒に書かせ、答えを知っている資料で先に合わせてみる。
- 確認は、仕事の重さに応じて行う。重い仕事は、出典を開いて専門家に確認する。

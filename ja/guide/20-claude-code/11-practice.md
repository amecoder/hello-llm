# 第11章 実習課題 — 自分だけの整理ツールを最初から作る

> **一言まとめ**: 第2〜10章で作った「整理ツール」を、**自分の手でもう一度ずつ**作ってみる課題が9つあります。最後の課題は、**自分のメモ**で自分だけのツールを作ることです。
> 課題ごとに「うまくいったか確認」のチェックリストがあるので、誰かに採点してもらわなくても、自分で確認できます。

この章の画面の名前は、2026年10月31日のmacOSデスクトップアプリ（韓国語の画面）を基準にしています。画面が違うときは、画面に見える名前に従ってください。

## 実習課題の進め方

1. **練習用のフォルダを新しく作ります。** 例: `정리도구-연습`。その中に`inbox`フォルダを作り、[第2章の練習用メモ](02-install.md#練習用フォルダを用意して選ぶ)5つを入れます。第9章の臨時会議のメモは、課題7で入れます。
2. **課題の「やってみること」に従って進めます。** 灰色のボックスの依頼をコピーして送ればできます。
3. **「うまくいったか確認」をひとつずつチェックします。** チェックできなかった項目があれば、「見直す場所」の章を読んで、その部分だけもう一度やってみてください。

課題1〜6は順番にやってください。前の課題の結果（ひな形・ルール・スキル）を、後ろの課題が使います。課題7・8は、課題6まで終えてからやります。**課題9は一番最後に**やります。

最初から全部やりきる必要はありません。1日に課題2〜3個ずつで十分です。結果は毎回少しずつ違います。このガイドの結果と形が違っても、チェックリストがすべてチェックできればうまくいっています。

### 実習で守る3つのこと

- **権限モードは「手動」にしておきます。** 何をしようとしているのかをひとつずつ見ながら、慣れていきます（[第4章](04-permissions-undo.md)）。
- **練習用のフォルダだけでやります。** 自分の文書がすべて入ったフォルダは選びません（[第2章](02-install.md)）。
- **課題9の自分のメモは、個人情報を消して**から入れます（[第9章](09-cost-data-safety.md)）。

## 課題

### 課題1. 最初の整理を任せる

**こんなとき**: 会議が終わって、ごちゃごちゃのメモを議事録にしたいとき。

**やってみること**: Codeタブで新しいセッションを開き、フォルダを選んでから送ります。

```
inboxフォルダの会議メモを読んで、議事録として整理して。決めたこと / やること（担当・期限）/ 次に話し合うことの3つに分けて、notesフォルダに新しいファイルで保存して。元のメモは書き換えないで。
```

**うまくいったか確認**

- ☐ やることごとに、担当と期限がある
- ☐ セットの価格（5,500ウォン）と次の会議（11/3）が、メモと同じ
- ☐ メモにない内容を作っていない
- ☐ inboxの元のメモはそのままだ

**見直す場所**: [第2章 デスクトップアプリのインストールと最初のセッション](02-install.md)

### 課題2. 変更の記録をオンにして、変わった内容を見る

**こんなとき**: Claudeが何を変えたのかを、行単位で見たいとき。

**やってみること**: タイトル行の変更内容ボタンを押して「Gitリポジトリが必要です」と出たら、下の2つの依頼を順番に送ります。

```
変わった内容を見るには、Gitリポジトリが必要なんだって。このフォルダで変更の記録（Git）をオンにして、今あるファイルを最初の記録として残して。何をしたのかをやさしく説明して。
```

```
議事録のやること表に「状態」の欄を追加して。inboxの振り返りメモ3つを見て、終わったことは「完了（日付）」、まだなら「進行中」と書いて。振り返りにないことは「要確認」と書いて、他の部分は書き換えないで。
```

**うまくいったか確認**

- ☐ 変更内容の欄に、赤と緑の行と`+N −N`が見える
- ☐ やること表以外の行は変わっていない
- ☐ 電球・文具・原価は完了で、インスタは進行中だ
- ☐ 最初の記録に付いた名前とメールを確認した（会社のアカウントではないか）

**見直す場所**: [第3章 画面を見て回る](03-screen-tour.md)

### 課題3. 巻き戻して、なかったことにする

**こんなとき**: 結果が気に入らなくて、依頼する前に戻りたいとき。

**やってみること**: 勉強のメモの整理を任せたあと、入力欄に`/rewind`と入力して、その依頼の前まで巻き戻します。

```
inboxの勉強のメモを勉強ノートとして整理して。重要な内容 / わからない言葉の説明 / 質問すること / やってみること の4つに分けて、notesフォルダに新しいファイルで保存して。元のメモは書き換えないで。
```

**うまくいったか確認**

- ☐ 巻き戻しの確認ウィンドウで、`+0 −N`を先に読んだ
- ☐ 「コードと会話」で巻き戻したあと、勉強ノートのファイルが消えた
- ☐ 巻き戻した依頼が、入力欄にまた入っている

**見直す場所**: [第4章 許可と元に戻す](04-permissions-undo.md)

### 課題4. 計画モードでひな形3種を作る

**こんなとき**: 大きな仕事を任せる前に、進め方から見て直したいとき。

**やってみること**: 新しいセッションで権限モードを「計画」に変えて送ります。計画が出たら「仮定」の節を読み、ひとつ以上を「修正…」で変えてから「承認」します。

```
議事録・勉強ノート・週次の振り返りを、毎回同じ形で作りたいよ。notesフォルダの議事録とinboxのメモを参考にして、templatesフォルダにひな形を3つ作る計画を立てて。ひな形ごとにどんな欄を入れて、各欄に何を書くのか、そして結果が合っているかを私が確認するチェックリストも計画に入れて。
```

**うまくいったか確認**

- ☐ 計画が出ている間、自分のフォルダのファイルは変わらなかった（計画の文書だけが書かれる）
- ☐ 「修正…」で変えた点が、再び出てきた計画に反映された
- ☐ templatesフォルダに、ひな形3つとチェックリストができた

**見直す場所**: [第5章 上手な任せ方](05-delegate-well.md)

### 課題5. CLAUDE.mdにルールを保存して試す

**こんなとき**: 毎回同じルールを、また言っているとき。

**やってみること**: ルール3〜5個でCLAUDE.mdを作らせたあと、**新しいセッション**で、形式を伝えずに送ります。

```
inboxの振り返りメモ3つで、今週の週次の振り返りを書いて。
```

**うまくいったか確認**

- ☐ CLAUDE.mdが20行前後で短い
- ☐ 新しいセッションの結果が、ひな形と日付の形式のルールを守っていた
- ☐ メモにない欄に`(メモになし)`が書かれている

**見直す場所**: [第6章 プロジェクトの記憶](06-claude-md.md)

### 課題6. スキル3つでツールを完成させる

**こんなとき**: 同じ整理を、一行のコマンドで動かしたいとき。

**やってみること**: スキル3つ（meeting-notes・study-notes・weekly-review）を作らせます。許可ウィンドウが出たら、プレビューを読んで「一度だけ許可」を選びます。そのあと、新しいセッションで一行で呼び出します。

```
/study-notes inbox/공부-2026-10-28-프롬프트-강의.txt
```

**うまくいったか確認**

- ☐ `/`を入力して名前の一部を入力したとき、スキルが一覧に出る
- ☐ 一行のコマンドで、ひな形の順番どおりのノートが出た
- ☐ 許可ウィンドウで「常に許可」ではなく「一度だけ許可」を選んだ

**見直す場所**: [第7章 スキル・プラグイン・外部ツール](07-skills-plugins.md)

### 課題7. 隠れた指示の実験をする

**こんなとき**: 他人から届いた資料を整理させるときの注意点を、体で覚えたいとき。

**やってみること**: 第9章の[臨時会議のメモ](/practice/notes/inbox/회의-2026-10-29-임시회의.txt)をinboxに入れて、整理させます。

```
/meeting-notes inbox/회의-2026-10-29-임시회의.txt
```

**うまくいったか確認**

- ☐ 議事録の最後に「すべてのやること完了」が**ない**
- ☐ Claudeの答えに、そのお知らせについての説明があるかを確認した
- ☐ 結果がどうであっても、他人の資料はざっと目を通してから任せるという心得を書いておいた

**見直す場所**: [第9章 コスト・データ・安全](09-cost-data-safety.md)

### 課題8. 予約またはターミナルで動かしてみる

**こんなとき**: 整理ツールを自分が呼び出さなくても動くようにしたいとき、または一行で確認したいとき。

**やってみること**: 次の2つのうちのひとつをやります。

- 金曜日の週次の振り返りの**予約**を、言葉で頼んで作り、**Run now**で一度動かしてみて、要らなければオフにする（[第8章](08-parallel-cloud-schedule.md)）。
- ターミナルで練習用のフォルダに移動して、読み取り専用の質問を`claude -p`で実行する（[第10章](10-terminal.md)）。

```
notesフォルダのファイルの一覧を見せて、各ファイルがどのひな形（templatesのどれ）で書かれたかを一行ずつ教えて。ファイルは書き換えないで。答えは短く、表だけで。
```

**うまくいったか確認**

- ☐ （予約）依頼に「メモがなければ…」のような条件を入れた
- ☐ （予約）Run nowで出た許可ウィンドウを処理した
- ☐ （ターミナル）同じフォルダのひな形ファイルを、ターミナルも読み取れた

**見直す場所**: [第8章](08-parallel-cloud-schedule.md)、[第10章](10-terminal.md)

### 課題9. 自分のメモで自分だけの整理ツールを作る

**こんなとき**: もう練習ではなく、自分の仕事に使いたいとき。

**やってみること**: 新しいフォルダ（例: `내-정리도구`）に`inbox`を作り、**個人情報を消した**自分のメモを2〜3個入れます。そのあと、課題4〜6を自分の仕事に合わせてもう一度やります。

```
inboxのメモを読んで、私が毎週整理する文書のひな形を作る計画を立てて。どんな欄が必要になりそうか、先に私に質問して。答えを聞いてから、templatesにひな形を、.claude/skillsに整理スキルを作ろう。
```

**うまくいったか確認**

- ☐ 計画の前にClaudeが質問をして、自分の答えがひな形に反映された
- ☐ CLAUDE.mdに、自分のルールが3〜5行で入った
- ☐ スキルの一行で、自分のメモが自分のひな形どおりに整理される
- ☐ 結果を元のメモと照らし合わせるチェックリストがある
- ☐ 練習用のフォルダ（`정리도구-연습`など）は、要らなければ片付けた

**見直す場所**: [第5章](05-delegate-well.md)、[第6章](06-claude-md.md)、[第7章](07-skills-plugins.md)

# 第6章 在對話中不斷打磨

> **一句話總結**：AI 的第一次回答不是成品，而是初稿。在同一個對話裡邊改邊完善；
> 一旦對話開始變亂，就帶著摘要換到新對話裡。

## AI 能記住多少對話

### 在同一個對話裡，它記得

在同一個對話窗口裡來回說過的內容，AI 回答時都會一起讀。所以你說"把剛才那篇文章的第二段縮短一點"，
它就知道你指的是哪篇文章。

準確地說，AI 並不是把對話"存起來"。更像是**每次回答時，都把整段對話從頭重新讀一遍**。
想一想[第1章](01-what-is-llm.md)講過的**上下文視窗**（一次能讀進去的文字量）。對話還在這個範圍內的時候，AI 才能參考前面的內容。

這樣來回多次的對話叫作**多輪**（multi-turn）對話。**一輪**（turn）就是你說一次、AI 答一次。

### 在新對話裡，預設它不知道

開啟一個新的對話視窗時，AI 對之前的對話一無所知。昨天花了很久講清楚的情況，今天要重新告訴它。

有些服務有**記憶**（memory）功能，會記住之前對話的一部分。
不同服務的行為和設定方法不一樣，我們放到第2階段（各服務指南）再講。
這一章裡，請先按"新對話從零開始"來用。

## 怎樣把修改要求說清楚

回答不合心意時，最常見的錯誤是這樣說：

```
不怎麼樣。重寫。
```

AI 不知道哪裡不怎麼樣，所以只會給你一篇水平差不多的另一篇文章。要求修改時，請加上三樣東西。

| 要素 | 問題 | 例子 |
|---|---|---|
| **改哪裡** | 哪個部分有問題？ | "第三句""結論部分""整體語氣" |
| **怎麼改** | 想改成什麼樣？ | "更短一點""加上數字""別那麼生硬" |
| **哪些不動** | 必須保留什麼？ | "第一段很好，保持原樣" |

加上這三樣，就變成下面這樣。和"不怎麼樣"不同，要改的地方和要保留的地方都很清楚。

```
整體思路不錯。第三段太長了，幫我縮成兩句話。
最後一句的"謝謝"保持不變，其餘語氣保持現在這樣。
```

### 可以直接用的修改說法

| 遇到這種情況 | 可以這樣說 |
|---|---|
| 太長了 | "只留下核心，縮短到一半長度" |
| 太生硬了 | "改成像關係好的前輩跟後輩說話那樣" |
| 太老套了 | "去掉誰都會說的話，改成只適用於這個情況的內容" |
| 看不懂 | "這部分請舉個例子，讓初中生也能聽懂，再解釋一遍" |
| 想知道依據 | "告訴我你這樣想的三個理由" |
| 忘了最初的指示 | "請重新遵守我一開始說的條件（五句話以內，用敬語）" |

### 指示照做了卻沒用時——說出目標

你說"再短一點"，它真的變短了。可是重要的內容也一起被刪掉了。
這是 AI 守住了你話裡的字面，卻沒抓住你的意思。

這時候把同一句話說得更用力，通常也改不好。換個辦法，加上**你為了什麼這樣要求**。[^academy-goal]

**不夠好的例子**

```
再短一點。真的要很短。
```

**更好的例子**

```
再短一點。目標是讓忙碌的組長能讀到最後，
並且記住第二段裡的調查結果。
```

區別在最後一行。知道了目標，AI 才能判斷該留什麼、刪什麼。

"三行以內""做成表格"說的是形式，"讓團隊相信這個日程"說的才是目標（見[第4章「好提示詞的5個要素」](04-prompt-basics.md#好提示詞的5個要素)）。
發出請求之前，先問問自己：我只說了形式，還是也說了目標？

## 重新生成、修改提問、接著追問——什麼時候用哪個

大多數服務都有三種方法可以重新得到回答。按鈕的名稱和位置因服務而異，第2階段會配合畫面一起演示。

| 方法 | 做什麼 | 適合什麼時候 |
|---|---|---|
| **接著追問** | 在當前回答的基礎上，請它修改 | 方向對了，只需改一部分時 |
| **重新生成** | 用同一個問題再得到另一個回答 | 問題沒問題，只是這次回答碰巧不理想時 |
| **修改我的提問** | 把我發出的問題改一改再發一次 | 第一次提問漏了資訊時 |

為什麼對同一個問題按"重新生成"會得到不同的回答？就像[第1章](01-what-is-llm.md)講的，AI 在挑"下一個詞"的時候，
是從最合理的候選裡**按機率**挑的。所以同一個問題，每次的回答都會有一點不同。

### 再點一次之前——先弄清楚問題出在哪

回答不對勁時，很容易先點"重新生成"。在那之前，先看看這是哪一類失敗。知道失敗的型別，就能直接用對應的辦法。[^academy-diagnose]

- **名字、數字、出處看起來很像真的，但讓人懷疑** → 回到原始資料去核對（[第9章](09-safety.md#核對的四個習慣)）。
- **在長對話裡忘了最初的條件** → 重新告訴它條件，或者帶著交接備忘錄換到新對話（見下面的[「什麼時候開始新對話」](#什麼時候開始新對話)）。
- **計算錯了** → 如果服務能用程式碼來計算，就請它這樣做。
- **無條件同意我的想法** → 告訴它可以提出反對意見（[第1章](01-what-is-llm.md#_5-容易附和我的話——諂媚)）。

如上表所示，重新生成適合"問題沒問題，只是回答碰巧不理想"的情況。如果原因另有所在，就先解決那個原因，而不是再點一次。

## 什麼時候開始新對話

一個對話拖得太久，回答反而會變差。因為前面聊過的內容會一直影響後面。
比如在同一個對話裡，先花很久做了店鋪宣傳文案，再請它寫簡歷，簡歷裡就可能混進宣傳文案的口氣。

![回答不滿意時：方向對，就指出要改的地方請它修改；方向錯了，而且對話很長或話題變了，就讓它寫摘要並開始新對話，否則把請求重寫一遍，在同一個對話裡再試](../../../guide/00-common/assets/ch6-decide.svg)

看到下面這些訊號，就開始新對話吧。

- **話題變了** —— 比如從規劃旅行轉到公司報告時
- **開始忘記最初的指示** —— 總是違反一開始定好的語氣或篇幅時
- **重複同樣的錯誤** —— 請它改了，類似的錯誤還是不斷出現時
- **對話變得非常長** —— 要往上翻很久才能看到開頭時

## 換到新對話的方法——摘要交接

開始新對話，並不意味著要丟掉目前為止定下來的東西。請**在原來的對話裡讓它寫一份摘要，再貼到新對話裡。**
這和公司裡換負責人時寫的工作交接備忘錄是一回事。

**在原來的對話裡**

```
我想在新對話裡接著做這件事。請按下面的專案寫一份交接備忘錄。
- 目標：正在做什麼
- 已確定的內容：到目前為止定下的內容和條件
- 我的偏好：我說過喜歡的和不喜歡的
- 剩下的事：接下來要做的事
```

**在新對話裡**

```
下面是我在之前的對話裡整理的交接備忘錄。請根據這些內容，從"剩下的事"的第一項開始接著做。

---
[貼上交接備忘錄]
---
```

請用[第5章](05-prompt-patterns.md)講的**分隔符**（`---`）把備忘錄括起來。這樣 AI 就不會把備忘錄的內容和我的請求混在一起。

## 把好用的提示詞存起來

改了好幾次才得到好結果的請求，別扔掉，收集到記事本里。下次遇到類似的事，只要換掉空格里的內容就能再用。

```
[整理週報用]
下面是我這周的工作筆記。請整理成要彙報給組長的週報。
做成"已完成 / 進行中 / 下週計劃"三欄的表格，每一項寫一行。

---
[本週筆記]
---
```

像這樣留出空格、可以反覆使用的請求，叫作**提示詞模板**（prompt template）。
有些服務還有功能，可以把這類指示存起來，每次自動應用。這個也放到第2階段再講。

## 動手試試

1. 在新對話裡，只請求"推薦一下下週五團隊聚餐的地方"。
2. 對得到的回答，加上**修改3要素**（改哪裡、怎麼改、哪些不動），請它修改兩次。
3. 讓它寫一份交接備忘錄，貼到**新對話**裡，接著說"按這些條件，幫我寫一條預訂諮詢簡訊"。

看看新對話的回答，問問自己：前面定好的人數、預算、地區這些條件，都保持住了嗎？

## 總結

- 在同一個對話裡，AI 會一起讀前面的內容；新對話則從零開始。
- 提修改要求時，要說清"改哪裡、怎麼改、哪些不動"。
- 話題變了，或者 AI 開始忘記最初的指示，就讓它寫交接備忘錄，換到新對話。
- 好用的請求存成模板，反覆使用。

## 術語整理

| 術語 | 中文名稱 | 一句話解釋 |
|---|---|---|
| Multi-turn | 多輪對話 | 來回多次的對話 |
| Turn | 輪 | 問一次、答一次的一個回合 |
| Context Window | 上下文視窗 | AI 一次能讀進去的文字量（[第1章](01-what-is-llm.md)） |
| Memory | 記憶 | 記住之前對話一部分內容的服務功能 |
| Regenerate | 重新生成 | 用同一個問題得到另一個回答 |
| Prompt Template | 提示詞模板 | 只換空格內容就能反覆使用的請求框架 |

# 第10章 實踐任務——從頭到尾走一圈

> **一句話總結**：把第 1~9 章的流程一口氣接起來做一遍。就是**計劃 → 製作 → 檢查 → 審查 → 釋出 → 運營 → 安全檢查**。
> 最後的任務是用**我自己的問題**從頭做起。請用檢查清單自己確認。

本章是彙總前面各章內容的任務章。依據在各章的腳註裡。**不需要一開始就完美。** 卡住了就回到那一章重新讀。

## 任務 1——待辦看板走一圈

如果你跟著前面各章的「親手試一試」做下來，這個任務就已經完成了。如果跳過了，就按順序做一遍。

| 順序 | 要做的事 | 章 |
|---|---|---|
| 1 | 在 GitHub 上建立公開倉庫 `cafe-todo-board`，並克隆到我的電腦上 | 2 |
| 2 | 接受 Claude 的採訪，寫出 SPEC.md | 3 |
| 3 | 用新會話和計劃模式拿到計劃，在分支上做出第一個介面 | 4 |
| 4 | 做一個檢查 SPEC.md 標準的裝置，並拿到證據 | 5 |
| 5 | 建 PR，經過與 SPEC.md 對照的審查後合併 | 6 |
| 6 | 公開之前用檢查清單確認秘密值和個人資訊 | 9 |
| 7 | 用 GitHub Pages 公開，並在手機上開啟 | 7 |
| 8 | 把改進寫成 Issue，用 `fixes #Issue編號` 再走一圈 | 8 |

## 任務 2——用我自己的問題從頭做起

從你的生活或工作裡挑一個**小小的不便**，用同樣的流程做一個網頁。比如這些。

- 檢視我們社團這個月的日程
- 我讀過的書和一句話感想的清單
- 店裡的選單和營業時間說明

第一個請求像第3章一樣，從採訪開始。

```
我想做一個解決<我的不便>的小網頁。我還沒有深入想過。請採訪我，直到可以寫出規格說明，全部完成後寫進 SPEC.md。因為要上傳到公開倉庫，所以我不會放進個人資訊。
```

**注意**：像店鋪說明這樣，如果要用在真正的生意上，請先確認第7章裡看到的 GitHub Pages 的禁止事項（經營生意、網店、商業服務）。當作練習來做，和用在真正的營業上，是不一樣的。

## 檢查清單

完成任務後，請逐項確認下面的內容。全部都是"是"，就說明這一圈走得很紮實。

**計劃**
- ☐ SPEC.md 的每一行都可以用是/否來確認。
- ☐ SPEC.md 裡有至少一行"不做的事"。

**製作**
- ☐ 用計劃模式讀了計劃，批准之後才開始製作。
- ☐ 不是在 `main` 上，而是在分支上製作的，一個提交只有一處改動。

**檢查**
- ☐ 有檢查裝置，並且拿到了執行過的命令和輸出這樣的證據。
- ☐ 看到了故意弄錯時檢查會失敗。

**審查**
- ☐ PR 說明裡寫了改了什麼、為什麼改。
- ☐ 在新會話裡接受了與 SPEC.md 對照的審查。即使沒有發現問題，也親自瀏覽過。

**釋出與運營**
- ☐ 公開地址在手機上也能開啟。
- ☐ 下一步改進已經寫成了 Issue。

**安全**
- ☐ 倉庫和頁面裡沒有秘密值、真名、聯絡方式。
- ☐ 有 `.gitignore`，並且寫進了可能含有秘密值的檔案。

來源：本指南的整理

## 用其他工具試試

第3階段用過的 Codex 和 Antigravity 裡也有對應的功能，可以走同樣的流程。

| 要做的事 | Codex | Antigravity |
|---|---|---|
| 先做計劃 | `/plan` | Planning mode |
| 檢視改動內容 | 審查視窗 | Review 視窗 |
| 規則檔案 | `AGENTS.md` | `AGENTS.md`·`GEMINI.md` |

來源：[Codex 第4章](../21-codex/04-permissions-undo.md)·[Antigravity 第 2、3 章](../22-antigravity/02-first-task.md)

把同一份 SPEC.md 交給兩個工具，比較結果，也是很好的練習。正如第3階段看到的，即使指令相同，每個工具漏掉的東西也可能不同。

## 小結

- 任務 1 用待辦看板，從計劃到安全檢查走一圈。
- 任務 2 用我自己的小小不便從頭做起。用在真正的生意上之前，要確認 Pages 的禁止事項。
- 檢查清單的每一格都是"是"，就說明這一圈走得很紮實。

# 5장. 누가 무엇을 볼 수 있나

<Badge type="tip" text="필수" /> 이 단계를 따라가려면 꼭 읽으세요.

> **한 줄 요약**: 만들기 전에 **누가 이 화면과 자료를 볼 수 있는지** 정합니다. 내 컴퓨터 도구는 그 컴퓨터를 쓰는 사람, 공개 페이지는 **세상 모두**, 회사 도구는 내가 고른 사람입니다.
> 공개 페이지에는 비밀값과 개인정보를 넣지 않습니다. 회사 도구는 접근 설정을 **가장 좁은 것**부터 고릅니다.

## 혼자 쓰는 것과 같이 쓰는 것

보는 사람이 누구냐에 따라 지킬 것이 달라집니다. 트랙별로 정리하면 이렇습니다.

| 트랙 | 볼 수 있는 사람 | 가장 먼저 지킬 것 |
|---|---|---|
| 재테크 | 그 컴퓨터를 쓰는 사람 | 컴퓨터 잠금 |
| 가게 | 그 컴퓨터를 쓰는 사람(직원 포함) | 컴퓨터 잠금, 손님 명단에 적는 것 줄이기 |
| 게임 | 링크를 아는 누구나 | 페이지에 아무 비밀도 넣지 않기 |
| 업무 | 접근 설정으로 고른 사람 | 가장 좁은 접근 설정 |

내 컴퓨터 도구에는 로그인이 없습니다. 대신 **컴퓨터 자체가 문**입니다. 매장 컴퓨터를 켜 둔 채 자리를 비우면, 손님 명단도 함께 열려 있는 셈입니다. 자리를 비울 때 화면을 잠그세요. 윈도는 `윈도 키 + L`, 맥은 `Control + Command + Q`입니다.

처음 버전에 로그인을 넣지 않는 것은 게을러서가 아닙니다. 혼자 쓰는 도구에 로그인을 붙이면 비밀번호를 저장할 서버가 필요해지고, 일이 몇 배로 커집니다(2장). 문이 이미 있으면 그 문을 잘 잠그는 쪽이 낫습니다.

## 공개 페이지에는 모든 것이 보인다

게임처럼 인터넷에 공개한 페이지는 **화면에 안 보이는 것까지 공개**됩니다. 브라우저는 페이지를 보여 주려고 그 페이지의 파일(HTML·자바스크립트)을 통째로 받아 옵니다. 받은 파일은 누구나 열어 읽을 수 있습니다.

그래서 이런 것은 공개 페이지의 코드 어디에도 두면 안 됩니다.

- 인증키·비밀번호 같은 **비밀값**(8장)
- 친구 이름·연락처 같은 **개인정보**
- 「아무도 못 보게 숨겨 둔」 정답이나 관리자 메뉴

「화면에서 감추면 되지 않나?」 싶지만 감춘 것은 보이지 않을 뿐 받아 온 파일 안에 그대로 있습니다. 4단계에서 본 것처럼 GitHub Pages 사이트는 늘 공개되고, 무료 계정은 저장소까지 공개입니다([4단계 7장](../30-ai-sdlc/07-deploy.md)).

AI에게 공개 전에 한 번 훑게 하세요.

```text
이 폴더는 인터넷에 공개할 게임이야. 공개되면 안 되는 것이 있는지 모든 파일을 살펴봐 줘.
비밀값, 사람 이름, 연락처, 내 컴퓨터 경로, 숨겨 둔 관리자 기능을 찾아서 파일과 줄 번호로 알려 줘.
고치지는 말고 목록만.
```

## 회사 계정 안에서만 — 접근 설정

업무 트랙의 도구는 구글 Apps Script의 **웹 앱**으로 띄웁니다(6장). 웹 앱을 띄울 때 두 가지를 고릅니다.

**누가 쓸 수 있나**(access)는 넷 가운데 하나입니다.[^access]

| 설정 | 뜻 |
|---|---|
| 나만 | 띄운 사람만 쓸 수 있다 |
| 같은 도메인 | 띄운 사람과 같은 회사 계정(도메인)의 사람만 |
| 로그인한 누구나 | 구글 계정으로 로그인한 사람이면 누구나 |
| 아무나 | 로그인하지 않은 사람까지 |

「로그인한 누구나」는 **회사 사람만이라는 뜻이 아닙니다.** 구글 계정이 있는 세상 모든 사람입니다. 회사 동료만 쓰게 하려면 「같은 도메인」을 고릅니다. 이 선택지는 회사(구글 워크스페이스) 계정에서 띄울 때 의미가 있습니다.

**누구의 권한으로 실행하나**(execute as)는 둘 가운데 하나입니다.[^execute]

- **여는 사람으로**: 웹 앱을 연 사람의 권한으로 돈다. 그 사람이 볼 수 있는 시트만 읽고 쓴다.
- **띄운 사람으로**: 내 권한으로 돈다. 여는 사람이 시트에 권한이 없어도, 웹 앱을 거치면 내 시트를 읽고 쓴다.

「띄운 사람으로」는 편하지만, 웹 앱을 열 수 있는 사람은 **내 시트를 내 권한으로** 다룰 수 있게 됩니다. 그래서 「띄운 사람으로」를 고를 때는 「누가 쓸 수 있나」를 반드시 좁게 둡니다.

처음에는 「나만」으로 띄워 혼자 확인하고, 다 되면 「같은 도메인」으로 넓히세요. 좁은 데서 시작하면 실수해도 피해가 작습니다.

## 나중에 데이터베이스를 쓰게 되면

이 단계에서는 데이터베이스를 쓰지 않습니다. 하지만 다음 버전에서 손님용 예약 페이지나 온라인 점수판을 만들면 만나게 됩니다. 그때를 위해 하나만 기억하세요. **데이터베이스에는 「누가 어느 자료를 읽고 쓸 수 있나」 규칙을 따로 적어야 합니다.**

예를 들어 Firebase(구글의 데이터베이스 서비스) 문서는 「모두에게 허용」 규칙에 이렇게 경고를 붙여 둡니다. 실제 서비스에서 **절대** 쓰지 말라, 누구나 데이터베이스 전체를 덮어쓸 수 있다.[^firebase-open] Supabase(또 다른 데이터베이스 서비스)는 이 규칙(RLS)이 꺼진 표에 경고 표시를 띄우고 메일로 알립니다.[^supabase-rls]

AI가 「일단 다 열어 두고 나중에 막자」고 하면 멈추세요. 규칙은 처음부터 **막아 두고 필요한 만큼 여는** 쪽으로 씁니다.

## 직접 해 보기

1. SPEC.md의 「누가 쓰나」에 **볼 수 있는 사람**을 한 줄로 적는다(위 첫 표를 참고).
2. 아래 트랙 상자를 따라 한다.
3. 확인 기준에 「보면 안 되는 사람이 볼 수 없나?」를 내 트랙에 맞게 고쳐 적는다.

::: details 업무 트랙
SPEC.md에 이렇게 적어 둡니다.

- 누가 쓸 수 있나: 처음에는 「나만」, 확인이 끝나면 「같은 도메인」
- 누구의 권한으로: 직원이 시트를 직접 못 보게 하려면 「띄운 사람으로」, 각자 권한대로 쓰게 하려면 「여는 사람으로」

어느 쪽이 맞는지 모르겠으면 AI에게 「직원은 자기 신청만 적고, 합계는 총무팀만 본다. 접근 설정 두 가지를 어떻게 고르면 좋을지 이유와 함께 알려 줘」라고 물어보세요. 결정은 회사 규칙을 아는 내가 합니다.
:::

::: details 가게 트랙
손님 명단 칸을 다시 봅니다. **꼭 필요한 칸만** 남깁니다. 예시 꽃집 도구는 이름·연락처·메모·홍보 동의 여부만 둡니다. 생년월일, 주소처럼 쓰지 않는 칸은 처음부터 만들지 않습니다.

매장 컴퓨터를 직원과 함께 쓰면, 직원도 명단을 봅니다. 괜찮은지 정해 두세요.
:::

::: details 게임 트랙
「공개 페이지에는 모든 것이 보인다」의 프롬프트를 보냅니다. 나온 목록을 하나씩 지우거나 바꾸게 합니다.

게임 안에 친구 이름을 넣고 싶다면 실명 대신 별명을 쓰세요. 공개 페이지는 지운 뒤에도 Git 기록에 남습니다([4단계 9장](../30-ai-sdlc/09-safety.md)).
:::

::: details 재테크 트랙
내 컴퓨터에 다른 사람도 로그인한다면, 내 계정에 암호를 걸어 두세요. 대시보드는 브라우저 저장소에 거래 기록을 둡니다. 같은 컴퓨터 계정, 같은 브라우저를 쓰는 사람은 열 수 있습니다.

대시보드를 캡처해 남에게 보여 줄 때는 금액을 가리세요(10장).
:::

## 정리

- 내 컴퓨터 도구의 문은 컴퓨터다. 자리를 비우면 화면을 잠근다.
- 공개 페이지는 받아 간 파일까지 공개된다. 비밀값·개인정보·숨긴 기능을 넣지 않는다.
- Apps Script 웹 앱은 「누가 쓸 수 있나」와 「누구의 권한으로」를 고른다. 「로그인한 누구나」는 회사 사람만이 아니다.
- 데이터베이스의 접근 규칙은 막아 두고 필요한 만큼 연다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| Access | 액세스 | 무엇을 보고 쓸 수 있는 권한 |
| Domain | 도메인 | 여기서는 회사 계정이 함께 쓰는 주소(예: `@회사.com`) |
| Web app | 웹 앱 | 주소로 여는 프로그램. 여기서는 Apps Script로 띄운 페이지 |
| RLS | 알엘에스 | 데이터베이스에서 줄마다 누가 읽고 쓸지 정하는 규칙(Row Level Security) |

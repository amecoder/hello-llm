# 11장. 운영과 비용

<Badge type="tip" text="필수" /> 이 단계를 따라가려면 꼭 읽으세요.

> **한 줄 요약**: 이 단계의 결과물은 **무료로 운영**할 수 있습니다. 대신 무료 서비스마다 **한도**가 있고, 인증키처럼 **기한**이 있는 것도 있습니다. 달력에 적어 둡니다.
> 써 본 사람의 의견을 한곳에 모으고, 그중 **하나만** 골라 다음 버전을 만듭니다.

## 비용은 얼마나 드나

이 가이드의 네 트랙은 모두 돈을 내지 않고 시작합니다.

| 트랙 | 쓰는 것 | 비용 |
|---|---|---|
| 가게·재테크 | 내 컴퓨터, 브라우저 | 없음 |
| 게임 | GitHub Pages(공개 저장소) | 무료 계정으로 됨 |
| 업무 | 구글 시트, Apps Script | 구글 계정으로 됨 |
| 재테크(지표) | 한국은행 ECOS Open API | 인증키 발급 |

AI 도구의 구독료는 따로입니다. 3단계에서 고른 도구의 요금제를 그대로 씁니다.

가게 도구의 홍보 문구도 비용이 없습니다. 도구가 AI를 직접 부르지 않고, 내가 이미 쓰는 AI 채팅에 요청문을 붙여 넣기 때문입니다(10장). 도구가 AI를 직접 부르게 만들면 인증키와 사용료가 생깁니다. 처음 버전에서 굳이 그럴 필요는 없습니다.

## 한도와 기한 지켜보기

무료에는 **한도**가 있습니다. 넘으면 멈추거나 느려집니다. 내 트랙에 해당하는 것만 알아 두세요.

- **GitHub Pages**: 게시된 사이트는 1GB 이하, 한 달에 보내는 데이터는 100GB가 느슨한 한도입니다([4단계 7장](../30-ai-sdlc/07-deploy.md)). 작은 게임은 여기에 닿기 어렵습니다.
- **Apps Script**: 스크립트 한 번 실행은 **6분**까지입니다. 하루 한도는 사람마다 따로 세고, 처음 요청한 때부터 24시간 뒤 다시 채워집니다.[^quota] 구글은 이 한도를 **예고 없이 바꿀 수 있다**고 적어 둡니다.[^quota-change]
- **구글 시트**: 셀 2천만 개 또는 100MB(4장).

**기한**도 있습니다. 재테크 트랙의 ECOS 인증키는 발급일부터 **2년** 동안 쓰고, 연장해야 계속 씁니다(4장). 키를 받은 날 달력에 「ECOS 키 연장」을 2년 뒤로 적어 두세요. 기한이 지나면 받기 스크립트가 어느 날 갑자기 실패합니다.

한도와 기한은 **바뀝니다.** 이 가이드에 적은 숫자는 확인 날짜의 값입니다. 오래 쓸 도구라면 반년에 한 번 공식 문서를 다시 보세요.

## 의견 모으기

써 본 사람의 의견은 흩어지기 쉽습니다. 메신저, 말, 메모지. **한곳에 모으는 것**이 먼저입니다.

- 게임: GitHub **이슈**(할 일과 의견을 적는 기록)에 모읍니다. 4단계 8장에서 쓴 방법 그대로입니다([4단계 8장](../30-ai-sdlc/08-operate.md)).
- 가게·재테크·업무: 저장소나 작업 폴더에 `의견.md` 파일을 하나 두고, 날짜와 한 줄씩 적습니다.

적을 때는 **들은 그대로** 적고, 내 생각은 따로 적습니다.

| 아쉬운 기록 | 나은 기록 |
|---|---|
| 검색 기능 필요 | 11-20 직원: 「단골 이름이 기억 안 나서 전화번호로 찾고 싶어요」 |
| 게임 어려움 | 11-21 친구: 「돌이 너무 빨리 떨어져서 30초 만에 끝났어」 |

나은 기록에는 **누가, 무엇을 하려다** 막혔는지가 있습니다. 그래야 AI에게 건넸을 때 진짜 문제를 고칩니다. 「검색 기능」만 적으면 엉뚱한 검색 창이 생길 수 있습니다.

## 다음 버전 정하기

의견이 쌓이면 다음 버전을 정합니다. 재료는 두 가지입니다. 2장에서 적은 **「처음 버전에 넣지 않는 것」**과 `의견.md` 입니다.

여기서 **하나만** 고릅니다. 한 번에 여러 개를 바꾸면, 고장 났을 때 무엇 때문인지 알기 어렵습니다. 9장의 되돌리기도 어려워집니다.

```text
SPEC.md의 「처음 버전에 넣지 않는 것」과 의견.md를 읽어 줘.
다음 버전에서 할 만한 것을 세 개 골라, 각각 얼마나 큰 일인지(작음·중간·큼)와 로그인·서버·결제가 필요한지 표로 보여 줘.
고르는 것은 내가 할게. 아직 아무것도 고치지 마.
```

하나를 고르면 **2장으로 돌아갑니다.** SPEC.md를 고치고, 화면을 만들고, 7장처럼 확인하고, 9장처럼 백업한 뒤 바꿉니다. 이 한 바퀴가 운영입니다.

## 직접 해 보기 — 의견 1건 반영

1. 10장에서 보낸 사람에게 받은 반응, 7장에서 적은 막힌 곳을 `의견.md`(게임은 이슈)에 옮겨 적는다.
2. 「다음 버전 정하기」의 프롬프트로 후보 셋을 받고, **작은 것 하나**를 고른다.
3. SPEC.md를 고치고, 만들고, 7장처럼 확인한다.
4. 반영했으면 의견 옆에 「반영 11-25」처럼 적는다(게임은 PR에 `fixes #번호`).

::: details 업무 트랙
Apps Script를 고쳤으면 새 버전을 만들고 배포가 그 버전을 쓰게 합니다(6장). 동료에게 무엇이 바뀌었는지 한 줄로 알립니다.

하루에 여러 번 자동으로 도는 기능(트리거)을 넣고 싶다면, 하루 실행 시간 한도가 있다는 것을 먼저 AI에게 확인하게 하세요.[^quota]
:::

::: details 가게 트랙
고치기 전에 **백업 파일을 내려받습니다**(9장). 고친 뒤 자료가 그대로 보이는지 확인합니다. 저장 모양이 바뀌는 변경이면, AI에게 「예전 백업 파일도 그대로 되돌릴 수 있게 해 줘」라고 꼭 붙입니다.
:::

::: details 게임 트랙
의견은 이슈로, 반영은 브랜치와 PR로 합니다(4단계 6·8장). PR에 `fixes #번호` 를 쓰면 합칠 때 이슈가 닫힙니다. 공개 주소에서 바뀐 것을 확인하고, 의견을 준 친구에게 알려 줍니다.
:::

::: details 재테크 트랙
달력에 ECOS 키 연장일을 적었는지 확인합니다. 계산 규칙을 바꾸는 변경이면 7장의 테스트에 새 예를 먼저 넣고, 손으로 검산한 뒤 만듭니다.
:::

## 정리

- 네 트랙 모두 무료로 시작한다. AI 도구 구독료는 따로다.
- 무료 한도와 기한(인증키 2년)을 알아 두고 달력에 적는다. 한도는 바뀌니 가끔 다시 확인한다.
- 의견은 한곳에 들은 그대로 모은다. 누가 무엇을 하려다 막혔는지 적는다.
- 다음 버전은 하나만 골라 2장부터 한 바퀴 돈다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| Quota | 쿼터 | 무료로 쓸 수 있는 양의 한도 |
| Issue | 이슈 | 할 일과 의견을 적어 두는 GitHub 기록 |
| Feedback | 피드백 | 써 본 사람의 의견 |
| Trigger | 트리거 | 정한 때가 되면 스크립트를 저절로 돌리는 장치 |

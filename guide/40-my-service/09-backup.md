# 9장. 고장과 되돌리기

<Badge type="tip" text="필수" /> 이 단계를 따라가려면 꼭 읽으세요.

> **한 줄 요약**: 매일 쓰는 도구는 언젠가 고장 납니다. **자료는 백업 파일로**, **코드는 Git 기록으로**, **구글 시트와 웹 앱은 버전 기록으로** 되돌립니다.
> 되돌리기는 고장 난 날 처음 해 보면 늦습니다. 이 장에서 **한 번 미리 연습**합니다.

## 무엇을 어디로 되돌리나

고장은 두 종류입니다. **자료가 사라지는 것**과 **코드가 망가지는 것**입니다. 되돌리는 곳이 다릅니다.

| 무엇이 | 트랙 | 되돌리는 곳 |
|---|---|---|
| 자료(예약·손님·거래 기록) | 가게·재테크 | 내가 내려받은 백업 파일 |
| 자료(시트의 줄) | 업무 | 구글 시트의 버전 기록 |
| 코드 | 게임·가게·재테크 | Git 기록(커밋) |
| 띄워 둔 웹 앱 | 업무 | Apps Script 배포의 버전 |

자료와 코드를 나눠 생각하면 덜 당황합니다. 예를 들어 꽃집 도구에서 예약이 다 사라졌다면, 코드를 되돌려도 예약은 안 돌아옵니다. 백업 파일이 있어야 돌아옵니다.

## 자료 백업

4장에서 본 대로 브라우저 저장소의 자료는 「인터넷 사용 기록 삭제」 한 번에 사라질 수 있습니다. 그래서 **정해진 날에 백업**합니다.

- 가게: 「백업」 탭에서 자료 전체를 파일로 내려받습니다. 예시 꽃집 도구는 마지막 백업 날짜를 화면에 보여 줘서, 오래됐으면 바로 알 수 있습니다. 일주일에 한 번이 알맞습니다.
- 재테크: 내가 불러온 **원래 CSV 파일**이 곧 백업입니다. 파일을 지우지 말고 한 폴더에 모아 두세요.

백업 파일을 둘 곳도 정합니다. 같은 컴퓨터에만 있으면 컴퓨터가 고장 날 때 함께 잃습니다. USB 메모리나, 내가 쓰는 클라우드 저장소에 한 부 더 두세요.

⚠️ 손님 명단이나 실제 거래 기록이 든 파일은 **Git 저장소에 올리지 마세요.** 비공개 저장소라도 자료가 내 컴퓨터 밖으로 나갑니다. AI에게 「백업 파일과 내 CSV가 커밋되지 않게 `.gitignore` 에 넣어 줘」라고 요청합니다. `.gitignore` 는 Git이 무시할 파일 목록입니다(4단계 2장).

## 이전 버전으로 되돌리기

**코드**는 Git이 기억합니다. 4단계에서 작은 단위로 커밋해 둔 이유가 여기 있습니다. 고친 뒤 이상해졌다면 AI에게 이렇게 말합니다.

```text
방금 바꾼 뒤로 예약 목록이 안 보여. 최근 커밋 다섯 개를 보여 주고, 어느 커밋에서 바뀌었을지 짚어 줘.
되돌릴 때는 기록을 지우지 말고, 그 커밋을 되돌리는 새 커밋을 만들어 줘. 하기 전에 나에게 먼저 물어봐.
```

「기록을 지우지 말고」를 붙이는 이유가 있습니다. 기록을 지우는 방식으로 되돌리면, 나중에 「그때 무엇을 바꿨더라」를 다시 볼 수 없습니다. 게임은 되돌린 커밋을 올리면 GitHub Pages도 그 모양으로 다시 게시됩니다.

**구글 시트의 자료**는 시트가 기억합니다. 오른쪽 위 「마지막 수정」을 눌러 버전 기록을 열고, 오른쪽 패널에서 이전 버전을 고른 뒤 **이 버전 복원**을 누릅니다.[^sheet-history]

**Apps Script 웹 앱**은 배포가 기억합니다. 6장에서 본 대로 배포는 정해진 **버전**의 코드를 씁니다. 배포를 고쳐 버전을 바꿀 수 있습니다.[^deploy-edit] 새 버전에 문제가 있으면 배포가 잘 되던 이전 버전을 쓰도록 고칩니다.

## 고장 알아채기

되돌리려면 먼저 고장 난 것을 알아야 합니다. 사용자가 「안 돼요」라고 말해 주기 전에 내가 먼저 아는 습관 세 가지입니다.

- **고친 뒤에는 쓰는 곳에서 한 번 연다.** 게임은 공개 주소, 업무는 동료와 같은 주소, 가게는 매장 컴퓨터. 내 작업 화면에서만 보면 놓칩니다.
- **마지막 백업 날짜를 본다.** 일주일이 넘었으면 오늘 합니다.
- **이상하면 화면을 캡처해 둔다.** 「언제, 무엇을 했더니, 무엇이 보였나」를 한 줄 적어 AI에게 건네면 원인을 빨리 찾습니다.

화면이 하얗게 비거나 버튼이 반응하지 않으면, 브라우저가 속으로 오류를 기록했을 수 있습니다. AI에게 「화면이 비어. 브라우저 개발자 도구의 콘솔에 나온 오류를 보는 방법을 알려 주고, 거기 나온 글을 읽고 원인을 찾아 줘」라고 하세요. 개발자 도구는 브라우저에 들어 있는, 페이지 속을 들여다보는 창입니다.

## 직접 해 보기 — 백업 1회, 되돌리기 1회

이번 장은 **실제로 한 번씩 해 보는 것**이 과제입니다.

1. 내 트랙 상자의 「백업」을 한다.
2. 같은 상자의 「되돌리기 연습」을 한다.
3. 둘 다 됐으면 7장의 `확인기록.md` 에 날짜와 결과를 한 줄 적는다.

::: details 업무 트랙
- 백업: 시트는 버전 기록이 자동으로 남습니다. 연습용 줄을 하나 지운 뒤 버전 기록에서 그 전 버전을 복원해 봅니다.
- 되돌리기 연습: 웹 앱에 작은 변경(제목 글자 바꾸기)을 하고 새 버전으로 배포합니다. 그다음 배포가 이전 버전을 쓰도록 고쳐, 제목이 원래대로 돌아오는지 봅니다.

참고 문서: [배포 만들고 관리하기](https://developers.google.com/apps-script/concepts/deployments)
:::

::: details 가게 트랙
- 백업: 「백업」 탭에서 파일을 내려받아 USB나 클라우드에 한 부 더 둡니다.
- 되돌리기 연습: **평소에 안 쓰는 다른 브라우저**에서 `index.html` 을 엽니다. 자료가 비어 있을 것입니다. 거기서 백업 파일로 되돌리고, 예약과 손님이 그대로 보이는지 봅니다. 매장 컴퓨터가 고장 났을 때 새 컴퓨터에서 하는 일과 같습니다.
:::

::: details 게임 트랙
- 백업: 코드는 GitHub 저장소에 이미 있습니다. 최근 변경이 모두 커밋·푸시됐는지 확인합니다.
- 되돌리기 연습: 게임 제목 글자를 바꿔 커밋·푸시하고 공개 주소에 반영된 것을 봅니다. 그다음 「이전 버전으로 되돌리기」의 프롬프트로 그 커밋을 되돌리고, 공개 주소의 제목이 원래대로 돌아오는지 봅니다.
:::

::: details 재테크 트랙
- 백업: 지금까지 불러온 CSV 파일을 한 폴더에 모으고, USB나 클라우드에 한 부 더 둡니다. `.gitignore` 에 들어 있는지도 확인합니다.
- 되돌리기 연습: 대시보드의 「저장한 내 자료 지우기」를 누른 뒤, 모아 둔 CSV를 다시 불러와 숫자가 전과 같은지 봅니다.
:::

## 정리

- 자료와 코드를 나눠서 되돌린다. 자료는 백업 파일·시트 버전 기록, 코드는 Git, 웹 앱은 배포 버전.
- 브라우저 저장소의 자료는 정해진 날에 파일로 백업하고, 다른 곳에 한 부 더 둔다. 진짜 자료 파일은 Git에 올리지 않는다.
- 코드는 기록을 지우지 않고 되돌리는 새 커밋으로 되돌린다.
- 고친 뒤에는 쓰는 곳에서 연다. 되돌리기는 미리 한 번 연습한다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| Backup | 백업 | 사라질 때를 대비해 따로 둔 복사본 |
| Restore | 리스토어 | 백업이나 이전 버전으로 되돌리는 것(복원) |
| Rollback | 롤백 | 배포한 것을 이전 버전으로 돌리는 것 |
| Version history | 버전 히스토리 | 파일이 바뀌어 온 기록(버전 기록) |
| Developer tools | 디벨로퍼 툴스 | 브라우저 안의, 페이지 속을 들여다보는 창(개발자 도구) |

# 2장. 아이디어를 설명서로

<Badge type="tip" text="필수" /> 이 단계를 따라가려면 꼭 읽으세요.

> **한 줄 요약**: 한 줄 아이디어를 AI에게 건네고 **인터뷰를 받아** SPEC.md(설명서)를 만듭니다.
> 5단계의 SPEC.md에는 4단계보다 세 가지가 더 들어갑니다. **넣지 않는 것**, **자료는 어디에**, **확인 기준**입니다.

## 인터뷰받고 설명서 쓰기

SPEC.md는 무엇을 만들지 적은 설명서입니다. 4단계 3장에서 처음 만들어 봤습니다. 방법은 같습니다. 다 정리해서 쓰지 말고, **AI에게 나를 인터뷰하게** 합니다([4단계 3장](../30-ai-sdlc/03-plan-spec.md)).

5단계에서는 인터뷰 요청에 한 가지를 더 붙입니다. **누가 쓰고, 자료가 어디에 있는지**도 물어보라고 하는 것입니다. 이 둘이 뒤 장의 선택을 거의 다 정하기 때문입니다.

```text
「꽃집 사장님이 매장 컴퓨터에서 전화 예약·메뉴판·손님 명단을 관리하는 도구」를 만들고 싶어.
아직 깊이 생각해 보지 않았어. SPEC.md를 쓸 수 있을 때까지 나를 인터뷰해 줘.
질문은 한 번에 하나씩, 고를 수 있는 보기를 붙여 줘.
누가 쓰는지, 자료를 어디에 두는지, 처음 버전에서 뺄 것도 꼭 물어봐 줘.
다 되면 SPEC.md를 「한 줄 소개 / 누가 쓰나 / 처음 버전에 넣는 것 / 처음 버전에 넣지 않는 것 / 자료는 어디에 / 확인 기준」 순서로 써 줘.
```

질문을 하나씩 받으면 답하기 쉽습니다. 보기가 있으면 생각해 보지 않은 부분도 고르기만 하면 됩니다.

인터뷰가 끝나면 SPEC.md를 **소리 내어 읽듯이** 한 번 읽어 보세요. 내가 말한 적 없는 기능이 들어 있으면 지우라고 합니다.

## 처음 버전 줄이기

처음 버전은 **매일 쓰기 시작할 수 있는 가장 작은 모양**입니다. 넣고 싶은 것이 많아도, 처음 버전에는 꼭 필요한 것만 둡니다. 작으면 빨리 쓰기 시작하고, 써 보면서 진짜 필요한 것을 알게 됩니다.

그래서 이 단계의 SPEC.md에는 **「처음 버전에 넣지 않는 것」** 칸이 있습니다. 빼기로 한 것을 적어 두면 AI가 멋대로 덧붙이지 않고, 나중에 다음 버전 목록으로 그대로 씁니다(11장).

예시로 만든 세 도구가 뺀 것은 이렇습니다.

| 예시 | 처음 버전에 넣지 않은 것 | 뺀 이유 |
|---|---|---|
| 별똥별 받기(게임) | 친구끼리 겨루는 온라인 점수판 | 서버와 로그인이 필요하다 |
| 모퉁이 꽃집(가게) | 손님용 예약 페이지, 결제, 문자 자동 발송 | 인터넷 공개와 사업자 절차가 먼저다 |
| 내 돈 대시보드(재테크) | 증권사 계좌 자동 연결, 무엇을 사라는 추천 | 연결 절차가 크고, 조언은 이 도구의 일이 아니다 |

뺀 것 가운데 상당수는 「로그인」「서버」「결제」입니다. 이 셋은 일을 몇 배로 키웁니다. 처음 버전에서 이 셋을 빼면 대부분 혼자서도 끝까지 갈 수 있습니다.

뭘 빼야 할지 모르겠으면 AI에게 물어보세요.

```text
SPEC.md의 「처음 버전에 넣는 것」을 읽고, 매일 쓰기 시작하는 데 꼭 필요하지 않은 것을 골라 줘.
특히 로그인·서버·결제가 필요한 것이 있으면 따로 표시해 줘.
고르기만 하고 SPEC.md는 아직 고치지 마.
```

「아직 고치지 마」를 붙이면 내가 고른 뒤에 고치게 됩니다. 빼는 결정은 내가 합니다.

## 확인 기준은 질문으로

**확인 기준**은 다 만들었는지 판단하는 물음입니다. 4단계 5장에서 본 「확인 장치」의 바탕이 됩니다. 기준이 없으면 AI도 나도 언제 끝났는지 알 수 없습니다.

확인 기준은 **화면을 보는 사람이 예·아니요로 답할 수 있는 질문**으로 씁니다.

| 아쉬운 기준 | 나은 기준 |
|---|---|
| 잘 동작한다 | 새로 고침해도 적어 둔 예약이 남아 있나? |
| 휴대폰에서도 된다 | 휴대폰 세로 화면에서 게임을 끝까지 할 수 있나? |
| 오류를 잘 처리한다 | 첫 줄이 틀린 파일을 넣으면 무엇이 틀렸는지 쉬운 말로 알려 주나? |

나은 기준은 해 보면 바로 답이 나옵니다. 7장에서 이 질문들을 하나씩 직접 해 봅니다.

5단계에서는 진짜 데이터를 다루니, 기준에 이런 질문도 넣어 두세요.

- 자료가 사라지지 않나?(새로 고침, 창 닫았다 열기)
- 이상한 글자를 넣어도 화면이 깨지지 않나?
- 보면 안 되는 사람이 볼 수 없나?

## 직접 해 보기

1. 1장에서 적은 한 줄 아이디어로 「인터뷰받고 설명서 쓰기」의 프롬프트를 보낸다. 꽃집 부분을 내 한 줄로 바꾼다.
2. 질문에 답하고 SPEC.md를 받는다. 4단계처럼 내 저장소 폴더에 둔다(가게·재테크는 **비공개** 저장소).
3. 「처음 버전 줄이기」의 프롬프트로 뺄 것을 고르고, 고른 것을 「넣지 않는 것」으로 옮기게 한다.
4. 확인 기준이 모두 예·아니요 질문인지 읽어 본다.

트랙별로 SPEC.md에 꼭 들어가야 할 줄입니다.

::: details 업무 트랙
- **누가 쓰나**: 입력하는 사람과 합계를 보는 사람을 나눠 적는다(예: 직원은 신청, 총무팀은 합계)
- **자료는 어디에**: 구글 시트 한 개. 시트 이름과 칸 이름을 적는다(예: `신청` 시트, 칸은 `날짜, 이름, 품목, 수량`)
- **넣지 않는 것**: 결재 흐름, 메일 자동 발송(처음 버전은 입력·목록·합계만)
- 확인 기준 예: 「회사 계정이 아닌 사람이 주소를 열면 막히나?」
:::

::: details 가게 트랙
- **누가 쓰나**: 사장님과 직원. 손님은 이 도구를 보지 않는다
- **자료는 어디에**: 매장 컴퓨터의 브라우저 안. 다른 컴퓨터에서는 안 보인다는 것도 적는다(4장)
- **넣지 않는 것**: 인터넷 공개, 손님용 예약 페이지, 결제, 문자 자동 발송
- 확인 기준 예: 「`index.html` 을 더블클릭해서 열어도 동작하나?」
:::

::: details 게임 트랙
- **누가 쓰나**: 만든 나, 그리고 링크를 받은 친구(설치·가입 없이)
- **자료는 어디에**: 최고 기록만 그 기기의 브라우저에. 서버 없음
- **넣지 않는 것**: 온라인 점수판, 로그인, 광고
- 확인 기준 예: 「휴대폰 세로 화면에서 끝까지 할 수 있나?」
:::

::: details 재테크 트랙
- **누가 쓰나**: 나 혼자. 남에게 공개하지 않는다
- **자료는 어디에**: 내가 만든 거래 기록 파일(CSV, 쉼표로 칸을 나눈 표 파일)과, 출처를 밝힌 공공 자료(4장)
- **넣지 않는 것**: 증권사 계좌 연결, 실시간 시세, 무엇을 사라는 추천
- **계산 규칙**: 수익률을 어떻게 셀지 한 줄씩 적는다(예: 「달별 증감은 새로 넣은 돈을 빼고 센다」). 넣은 돈이 늘어난 것을 수익으로 착각하지 않게 하는 줄이다
:::

## 정리

- 한 줄 아이디어를 건네고 AI에게 인터뷰를 받아 SPEC.md를 만든다. 누가 쓰는지, 자료가 어디 있는지를 꼭 묻게 한다.
- 처음 버전은 매일 쓰기 시작할 수 있는 가장 작은 모양이다. 로그인·서버·결제는 먼저 뺀다.
- 뺀 것은 「넣지 않는 것」에 적어 둔다. 다음 버전 목록이 된다.
- 확인 기준은 예·아니요로 답하는 질문으로 쓴다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| SPEC.md | 스펙 엠디 | 무엇을 만들지 적은 설명서 파일 |
| Scope | 스코프 | 이번에 만드는 범위 |
| MVP | 엠브이피 | 쓰기 시작할 수 있는 가장 작은 처음 버전(Minimum Viable Product) |
| CSV | 씨에스브이 | 쉼표로 칸을 나눈 표 파일. 엑셀로도 열린다 |

# 7장. 진짜처럼 확인하기

<Badge type="tip" text="필수" /> 이 단계를 따라가려면 꼭 읽으세요.

> **한 줄 요약**: 진짜 사용자는 내가 예상하지 못한 것을 넣고 누릅니다. 그 전에 내가 먼저 **이상하게 써 봅니다.**
> 빈칸, 이상한 글자, 새로 고침, 휴대폰 너비, 틀린 파일을 넣어 보고, 계산은 **테스트**로 맡기고, 마지막에 **다른 사람**에게 써 보게 합니다.

## 이상한 입력 넣어 보기

AI가 「다 만들었어요」라고 해도, 보통은 **바르게 쓸 때**만 확인한 것입니다. 진짜 사용자는 칸을 비우고 저장을 누르고, 이름 칸에 메모를 길게 적습니다. 4단계 5장에서 본 「확인 장치」를 이번에는 이 방향으로 씁니다([4단계 5장](../30-ai-sdlc/05-test.md)).

이렇게 넣어 보세요.

| 넣어 볼 것 | 바라는 결과 |
|---|---|
| 칸을 비우고 저장 | 무엇이 빠졌는지 쉬운 말로 알려 준다 |
| 아주 긴 글(200자쯤) | 화면 모양이 깨지지 않는다 |
| 이름에 `<img src=x onerror=alert(1)>` | 그림이나 알림 창이 아니라 **글자 그대로** 보인다 |
| 첫 줄이 틀린 파일 | 어느 줄이 왜 틀렸는지 알려 준다 |

세 번째 줄이 낯설 수 있습니다. 화면에 글을 넣는 방법에 따라, 브라우저가 사용자가 적은 글을 **화면을 바꾸는 코드**로 읽어 버릴 때가 있습니다. 그러면 남이 적은 글이 내 화면에서 마음대로 돌 수 있습니다. 예시 꽃집 도구에 위 글을 넣으면 손님 이름이 그 글자 그대로 보였고, 그림은 하나도 생기지 않았습니다. 글을 늘 **글자로만** 넣게 만들었기 때문입니다.

AI에게 이 확인을 맡길 수도 있습니다.

```text
SPEC.md의 확인 기준과 아래 네 가지를 직접 해 보고 결과를 표로 알려 줘.
1. 칸을 비우고 저장 2. 200자 넘는 글 3. 이름에 <img src=x onerror=alert(1)> 4. 첫 줄이 틀린 파일
결과마다 「무엇을 넣었고, 화면에 무엇이 보였는지」를 적어 줘. 문제가 있어도 아직 고치지 마.
```

「무엇이 보였는지」를 적게 하면, 해 보지 않고 「괜찮습니다」라고 답하는 것을 막을 수 있습니다.

## 새로 고침과 휴대폰 너비

두 가지를 꼭 직접 해 봅니다.

- **새로 고침·창 닫았다 열기**: 자료가 남아 있나? 4장에서 본 대로 파일로 연 페이지는 브라우저마다 저장 동작이 다를 수 있습니다. 내가 쓸 브라우저에서 해 봐야 압니다.
- **휴대폰 너비**: 브라우저 창을 좁혀 보거나 실제 휴대폰으로 엽니다. 옆으로 넘치지 않나? 글자가 잘리지 않나?

예시를 만들 때 이 확인으로 **실제 문제 두 개**를 잡았습니다.

1. 재테크 대시보드가 휴대폰 너비에서 **옆으로 넘쳤습니다.** 표와 차트가 화면 밖으로 밀려 나갔습니다. 칸 너비를 정하는 규칙 하나가 원인이었고, AI가 고친 뒤 같은 너비에서 다시 재어 넘침이 사라진 것을 확인했습니다.
2. 차트 아래 **범례**(어느 색이 무엇인지 알려 주는 작은 표시) 색이 실제 선 색과 **달랐습니다.** 컴퓨터 화면에서는 대충 보면 놓치는 문제였습니다. 범례 색을 선 색에 맞춰 고쳤습니다.

둘 다 AI가 「다 됐어요」라고 한 뒤에 사람 눈으로 찾았습니다. 이상한 곳을 찾으면 **캡처를 건네며** 말하세요. 「여기 범례는 분홍인데 선은 하늘색이야」처럼 짚으면 빨리 고칩니다.

## 계산은 테스트로

수익률, 합계, 점수처럼 **계산**이 있는 도구는 눈으로만 확인하기 어렵습니다. 숫자가 그럴듯해 보여도 틀릴 수 있습니다. 이런 곳은 **테스트**(답이 정해진 예를 넣고 결과가 맞는지 자동으로 보는 코드)에 맡깁니다.

테스트를 쉽게 만들려면 **계산 규칙을 화면 코드와 나눠** 달라고 합니다. 예시 대시보드는 계산을 `logic.js` 한 파일에 모았고, 테스트가 그 파일만 불러 검사합니다. 게임도 규칙(점수·목숨·떨어지는 속도)을 따로 두어, 같은 시작값이면 같은 게임이 되는지 검사합니다.

```text
계산 규칙(SPEC.md의 「계산 규칙」)을 화면 코드와 다른 파일로 나눠 줘.
그리고 손으로 검산할 수 있는 작은 예를 넣는 테스트를 만들어 줘.
예: 7만 원에 10주, 8만 원에 10주를 사고 9만 원에 5주를 팔면, 남은 15주의 평균 단가는 7만 5천 원, 판 것 손익은 7만 5천 원.
테스트를 돌린 명령과 결과(몇 개 통과·실패)를 그대로 보여 줘.
```

예는 **손으로 셀 수 있는 숫자**로 고르세요. 테스트가 맞는지 내가 판단할 수 있어야 합니다. 예시 대시보드는 이런 테스트 9개, 꽃집 도구는 12개, 게임은 11개가 모두 통과한 뒤 다음 장으로 넘어갔습니다.

## 다른 사람에게 써 보게 하기

마지막 확인은 **나 아닌 사람**입니다. 만든 사람은 어디를 눌러야 하는지 이미 알아서, 막히는 곳을 못 봅니다.

방법은 간단합니다.

1. 할 일 하나만 말합니다. 「내일 3시에 꽃다발 예약 하나 적어 봐」처럼.
2. **도와주지 않고** 지켜봅니다. 손이 멈추는 곳, 「이거 뭐야?」라고 묻는 곳을 적습니다.
3. 끝나면 「제일 헷갈린 곳 하나」를 묻습니다.

적은 것은 그대로 AI에게 건넵니다. 「동료가 저장 버튼을 못 찾았다. 저장 버튼을 어디에 두면 좋을지 두 가지 안을 보여 줘」처럼 고칠 일로 바꿉니다. 고치는 일이 많으면 11장의 방법으로 목록을 만듭니다.

한 사람이면 충분합니다. 처음 써 보는 사람 한 명이 막히는 곳은 다른 사람도 대개 막힙니다.

## 직접 해 보기

1. 「이상한 입력 넣어 보기」의 프롬프트를 보내고 결과 표를 받는다. 내가 직접도 두세 가지 넣어 본다.
2. 새로 고침, 창 닫았다 열기, 휴대폰 너비를 직접 해 본다.
3. 계산이 있으면 「계산은 테스트로」의 프롬프트를 보낸다. 예는 내 트랙 숫자로 바꾼다.
4. 다른 사람 한 명에게 써 보게 하고, 막힌 곳을 적는다.
5. 찾은 문제를 고친 뒤 **같은 방법으로 다시 확인**하고, 결과를 `확인기록.md` 파일에 적어 커밋한다.

`확인기록.md` 는 한 줄씩이면 됩니다. 「2026-11-20 휴대폰 너비 넘침 → 고침 → 다시 재어 없음」처럼 날짜·무엇을·결과를 적습니다.

::: details 업무 트랙
- 동료 계정으로 열어, 같은 도메인 설정이 맞게 됐는지 본다. 회사 밖 개인 계정으로 열어 **막히는지**도 본다(5장).
- 두 사람이 거의 동시에 저장해도 두 줄이 다 남는지 본다.
- 시트에서 합계를 손으로 한 번 계산해 화면 합계와 맞춰 본다.
:::

::: details 가게 트랙
- 손님 이름에 이상한 글자를 넣는 확인은 꼭 한다. 명단은 매일 쌓인다.
- 예약을 완료·취소로 바꿨을 때 오늘 예약 목록과 방문 횟수가 맞게 바뀌는지 본다.
- 메뉴판을 실제로 인쇄해 본다. 화면의 버튼이 종이에 같이 찍히지 않는지 본다.
:::

::: details 게임 트랙
- 휴대폰 세로 화면에서 **끝까지** 한 판 한다. 끝 화면과 최고 기록이 나오는지 본다.
- 친구 한 명에게 링크만 보내고 아무 설명도 하지 않는다. 시작 버튼을 바로 찾는지 본다.
- 점수 규칙은 테스트로 맡긴다(같은 시작값이면 같은 게임이 되는지).
:::

::: details 재테크 트랙
- 지어낸 거래 기록 몇 줄로 평가손익·판 것 손익을 손으로 계산해, 화면 숫자와 맞춰 본다.
- 「구분」을 틀리게 적은 파일, 가진 것보다 많이 판 기록을 넣어 본다. 예시 대시보드는 「가진 것(15)보다 많이 팔았어요(20)」처럼 알려 준다.
- 범례 색과 선 색이 맞는지 차트마다 본다.
:::

## 정리

- 바르게 쓸 때만이 아니라 이상하게 써 본다. 빈칸, 긴 글, HTML 글자, 틀린 파일.
- 새로 고침과 휴대폰 너비는 직접 해 본다. AI가 「다 됐다」고 한 뒤에도 사람 눈이 문제를 찾는다.
- 계산은 화면과 나누고, 손으로 검산할 수 있는 예로 테스트를 만든다.
- 다른 사람 한 명에게 도와주지 않고 써 보게 한다. 고친 뒤에는 같은 방법으로 다시 확인한다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| Test | 테스트 | 답이 정해진 예를 넣어 결과가 맞는지 자동으로 보는 코드 |
| Edge case | 엣지 케이스 | 빈칸·아주 긴 글처럼 흔하지 않은 입력 |
| Legend | 레전드 | 차트에서 어느 색이 무엇인지 알려 주는 표시(범례) |
| Usability test | 유저빌리티 테스트 | 다른 사람이 써 보게 하고 막히는 곳을 찾는 일 |

# 8장. 메타 프롬프팅 — 프롬프트를 AI에게 만들게 하기

> **한 줄 요약**: 좋은 프롬프트를 직접 다 쓰지 않아도 됩니다. 생각나는 대로 쓴 요청을 AI에게 주고
> **"좋은 프롬프트로 바꿔 줘"** 라고 시키면 됩니다. 다만 AI가 정리한 결과는 보내기 전에 꼭 내가 한 번 읽습니다.

## 메타 프롬프팅이란

4장부터 7장까지 좋은 요청의 요소(목표·맥락·대상·형식·조건), 여러 패턴, 칸 나누기를 배웠습니다.
전부 외워서 매번 지키기는 어렵습니다. 그래서 **프롬프트를 쓰는 일 자체를 AI에게 맡기는** 방법이 있습니다.

이렇게 **프롬프트를 만들거나 고치게 하는 프롬프트**를 **메타 프롬프팅**(meta prompting)이라고 부릅니다.
"메타"는 "그 자체에 대한"이라는 뜻입니다. 질문에 대한 질문, 프롬프트에 대한 프롬프트라는 말입니다.

AI 회사들도 이 방법을 씁니다. OpenAI는 개발자용 연습 화면(Playground)의 Generate(만들기) 버튼이
**메타 프롬프트**(meta-prompt, 좋은 프롬프트를 만들거나 고치도록 지시하는 프롬프트)로 동작한다고 공개했습니다.[^openai-gen]
AI가 쓴 지시문이 사람이 쓴 지시문만큼, 때로는 더 잘 통한다는 연구도 있습니다.[^ape]

![메타 프롬프팅 순서: 생각나는 대로 쓴 내 요청 → AI가 구조화 프롬프트로 정리 → 내가 읽고 고치고 빈칸 채우기 → 새 대화에 붙여 넣어 보내기. AI에게는 정리만 시키고, 보내기 전 확인은 내가 한다](assets/ch8-meta.svg)

이 장에서는 쓰임새별로 네 가지 방법을 봅니다.

| 방법 | 이럴 때 |
|---|---|
| 1. 정리만 시키기 | 하고 싶은 말은 있는데 두서가 없을 때 |
| 2. 질문받으며 만들기 | 무엇을 적어야 할지조차 모를 때 |
| 3. 안 통한 프롬프트 고치기 | 요청했는데 원하는 답이 안 나왔을 때 |
| 4. 다시 쓸 틀로 만들기 | 같은 종류의 일을 자주 할 때 |

## 1. 정리만 시키기

가장 기본입니다. 생각나는 대로 쓴 요청을 주고, 7장에서 배운 칸으로 나눠 달라고 합니다.

**1단계 — 정리만 시키기**

```
아래 <my_request> 안의 내 요청을 XML 태그로 정리된 프롬프트로 바꿔 줘.
배경은 <context>, 붙여 넣은 자료는 <document>, 할 일은 <instructions>, 답의 모양은 <format>에 넣어 줘.
빠진 정보가 있으면 [여기에 ○○을 적어 주세요]처럼 빈칸으로 표시해 줘.
아직 요청을 실행하지는 말고, 정리된 프롬프트만 보여 줘.

<my_request>
다음 주 부모님 모시고 가는 제주 여행 일정 짜 줘 아버지 무릎이 안 좋으시고
렌터카 있고 2박 3일이야 맛집도 넣어 주고 비 오면 갈 곳도
</my_request>
```

두 문장이 중요합니다.
- **"빈칸으로 표시해 줘"**: 이 말이 없으면 AI가 빠진 정보를 그럴듯하게 지어서 채웁니다.
- **"아직 실행하지는 말고"**: 이 말이 없으면 AI가 정리하자마자 여행 일정까지 짜 버립니다.

**2단계 — 빈칸을 채워 다시 보내기**

AI가 돌려준 프롬프트에서 빈칸(예: 출발 날짜, 예산)을 채운 뒤, **새 대화**에 붙여 넣어 보내세요.
새 대화에 보내는 이유는 6장에서 본 것처럼, 정리하던 대화의 흔적이 답에 섞이지 않게 하기 위해서입니다.

> XML 태그 대신 "마크다운 제목으로 정리해 줘"라고 바꾸면 같은 방법으로 마크다운 프롬프트도 받을 수 있습니다.

## 2. 질문받으며 만들기

무엇을 적어야 할지 모르겠다면, AI가 나에게 **질문하게** 합니다.
5장의 「되묻게 하기」(Flipped Interaction) 패턴을 프롬프트 만들기에 쓰는 것입니다.

```
나는 우리 동네 반찬가게 홍보 문구를 AI에게 부탁하고 싶어.
그런데 어떤 정보를 줘야 좋은 답이 나오는지 모르겠어.
좋은 프롬프트를 만드는 데 필요한 것을 나에게 한 번에 하나씩 질문해 줘.
질문이 끝나면 내 답을 모아 XML 태그로 정리된 프롬프트를 만들어 줘.
```

AI는 "가게의 대표 메뉴는 무엇인가요?", "문구를 어디에 쓰실 건가요? 전단지, 인스타그램?"처럼 하나씩 묻습니다.
답하다 보면 **내가 미처 생각하지 못한 조건**(글자 수, 말투, 대상 손님)이 자연스럽게 채워집니다.

> **질문이 끝없이 이어지면**: "질문은 5개까지만 해 줘"라고 처음부터 개수를 정해 두세요.

## 3. 안 통한 프롬프트 고치기

요청했는데 답이 엉뚱하게 나왔다면, **내 프롬프트와 받은 답을 함께** 보여 주고 무엇이 문제였는지 묻습니다.
답만 보여 주면 AI는 어디가 문제인지 추측할 수밖에 없습니다.

```
아래 <my_prompt>로 요청했더니 <answer>처럼 답이 나왔어.
나는 초등학생 아이가 읽을 수 있는 쉬운 설명을 원했는데, 너무 어렵게 나왔어.

1. 내 프롬프트에서 무엇이 부족해서 이렇게 됐는지 짧게 설명해 줘.
2. 고친 프롬프트를 보여 줘. 바꾼 부분은 굵게 표시해 줘.

<my_prompt>
광합성 설명해 줘
</my_prompt>

<answer>
(받은 답 붙여 넣기)
</answer>
```

이 방법의 장점은 **고친 프롬프트와 함께 이유를 배운다**는 것입니다.
위 예시라면 "읽는 사람(대상)을 적지 않았다"는 설명이 돌아올 것이고, 이것은 4장의 5요소 중 하나입니다.
몇 번 하다 보면 처음부터 빠뜨리지 않게 됩니다.

> **"원하는 것"을 꼭 적으세요.** "답이 별로야, 고쳐 줘"만으로는 AI가 무엇을 기준으로 고칠지 모릅니다.
> 6장의 수정 요청과 같습니다. 무엇이, 왜, 어떻게 달라졌으면 하는지 말해야 합니다.

## 4. 다시 쓸 틀로 만들기

매주 쓰는 업무 보고, 매번 하는 회의록 정리처럼 **같은 일을 반복**한다면, 잘 통한 프롬프트를 **틀**(템플릿, template)로 만들어 둡니다.
바뀌는 부분만 빈칸으로 남긴 프롬프트입니다.

```
방금 우리 대화에서 회의록을 정리한 방식이 마음에 들어.
다음에도 같은 방식으로 쓸 수 있게, 매번 바뀌는 부분은 [회의 날짜] [회의록 원문]처럼
대괄호 빈칸으로 남긴 프롬프트 틀을 만들어 줘.
```

AI가 돌려준 틀을 메모장에 저장해 두고, 다음에는 빈칸만 채워서 새 대화에 보내면 됩니다.
이렇게 빈칸을 표시하는 `[ ]` 같은 표시를 **자리 표시자**(placeholder, 플레이스홀더)라고 부릅니다.

> 6장의 「인계 메모」가 대화 내용을 다음 대화로 넘기는 것이라면, 틀은 **요청 방식**을 다음에도 쓰게 넘기는 것입니다.

## 주의할 점

**1. AI가 내가 말하지 않은 조건을 끼워 넣습니다**

정리하면서 "예산 50만 원", "오전 9시 출발"처럼 임의의 값을 적을 때가 있습니다.
보내기 전에 정리된 프롬프트를 처음부터 끝까지 읽고, **내가 말하지 않은 내용**이 있으면 지우거나 고치세요.
이것이 이 장에서 가장 중요한 습관입니다.

**2. 길어졌다고 좋아진 것이 아닙니다**

메타 프롬프팅을 하면 프롬프트가 금세 몇 배로 길어집니다. 짧은 요청에는 오히려 짐이 됩니다.
"점심 메뉴 추천해 줘"를 정리시킬 필요는 없습니다. **결과가 실제로 나아졌는지**로 판단하세요.

**3. 정리된 프롬프트도 확인 대상입니다**

AI가 만든 프롬프트라고 해서 정답은 아닙니다. 프롬프트로 받은 답이 여전히 마음에 들지 않으면
3절처럼 다시 고치게 하거나, 직접 한두 줄을 고쳐도 됩니다.

## 직접 해 보기

최근에 AI에게 했던 요청 중 **답이 아쉬웠던 것** 하나를 떠올려 보세요.

1. 그 요청을 3절의 방법으로 AI에게 보여 주고, 무엇이 부족했는지와 고친 프롬프트를 받으세요.
2. 고친 프롬프트에서 **내가 말하지 않은 내용**에 표시해 보세요. 몇 군데나 있나요?
3. 표시한 부분을 내 뜻대로 고친 뒤 새 대화에 보내고, 처음 받은 답과 비교해 보세요.
4. 결과가 좋았다면 4절의 방법으로 틀을 만들어 메모장에 저장해 두세요.

## 정리

- 메타 프롬프팅은 프롬프트를 만들거나 고치는 일을 AI에게 맡기는 것이다.
- 두서없을 때는 정리만 시키고, 무엇을 적을지 모를 때는 질문받으며 만든다.
- 안 통한 프롬프트는 받은 답과 원하는 것을 함께 보여 주고 고치게 한다.
- 자주 하는 일은 빈칸이 있는 틀로 만들어 다시 쓴다.
- 보내기 전에 내가 말하지 않은 내용이 들어갔는지 꼭 읽는다.

## 용어 정리

| 용어 | 읽는 법 | 한 줄 뜻 |
|---|---|---|
| Meta Prompting | 메타 프롬프팅 | AI에게 프롬프트를 만들거나 다듬게 하는 것 |
| Meta-prompt | 메타 프롬프트 | 좋은 프롬프트를 만들거나 고치도록 지시하는 프롬프트 |
| Flipped Interaction | 플립드 인터랙션 (되묻게 하기) | AI가 나에게 질문하게 하는 패턴 (5장) |
| Prompt Template | 프롬프트 템플릿 (틀) | 바뀌는 부분만 빈칸으로 남겨 다시 쓰는 프롬프트 |
| Placeholder | 플레이스홀더 (자리 표시자) | 나중에 채울 빈칸을 나타내는 표시. 예: `[회의 날짜]` |

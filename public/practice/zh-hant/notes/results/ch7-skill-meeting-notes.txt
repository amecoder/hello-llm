# meeting-notes — 會議備忘 → 會議紀要

## 什麼時候用

- 會議結束後，要把 `inbox/meeting-YYYY-MM-DD-name.txt` 備忘整理成會議紀要的時候
- 例："把 10/27 週會的備忘整理成會議紀要"

## 要讀的檔案（按順序）

1. `CLAUDE.md` — 這個資料夾的 5 條整理規則
2. `templates/README.md` — 模板使用方法和檢查清單
3. `templates/minutes.md` — 要用的模板
4. 原始備忘 `inbox/meeting-YYYY-MM-DD-name.txt` — **只讀取。絕不修改。**

## 要用的模板

把 `templates/minutes.md` 原樣複製，只填 `{{ }}` 的位置。不改變欄目名稱·順序（1. 決定的事 → 2. 待辦事項 → 3. 下次要討論的事 → 4. 下次會議）。

各欄的填法：

- **開頭** — 地點·出席·原始備忘路徑。備忘裡沒有就寫 `（備忘中沒有）`。
- **1. 決定的事** — 只寫已經確定的事。一行寫清做什麼·多少/怎麼做·到什麼時候，重點加粗。備忘裡有提議人·暫緩的方案就補在後面。
- **2. 待辦事項** — 把備忘裡定下由誰來做的事**全部**搬進表格。備忘裡沒有負責人·期限的話，不要刪那一行，填上 `（備忘中沒有）`，再把同一件事以"負責人·期限未定"列進第 3 欄。狀態是 `預定` / `進行中` / `完成(MM/DD)` 三選一。
- **3. 下次要討論的事** — 沒有結論的議題、沒定下來的原因、做決定需要的東西。
- **4. 下次會議** — 像 `11/3(週一) 上午 10 點` 這樣寫。備忘裡沒有就寫 `（備忘中沒有）`。
- 沒有可寫內容的欄不要刪，寫上 `（備忘中沒有）`。

日期：標題按模板寫成 `2026-10-27(週一)`，正文寫成 `10/27(週一)` 這樣的月/日 + 括號星期。星期要對照日曆確認（`date -j -f %Y-%m-%d 2026-10-27 +%a`）。

**備忘裡沒有的內容不要編造。** 需要推測的話就不寫，寫 `（備忘中沒有）`。

## 儲存位置

- `notes/minutes-YYYY-MM-DD-meeting-name.md`（日期用原始備忘檔名裡的日期）
- 例：`inbox/meeting-2026-10-27-weekly.txt` → `notes/minutes-2026-10-27-weekly.md`
- 如果已經有同名檔案，覆蓋之前先問使用者。

## 完成後要核對的檢查清單

重新開啟儲存的檔案，從上往下確認。只要有一項 ✗，就改好後再確認一遍。

**通用**
- [ ] 欄目名稱和順序與模板相同（沒有刪掉的欄 — 沒有可寫的內容就寫 `（備忘中沒有）`）
- [ ] 一個 `{{` 也沒有剩下（`grep -n '{{' notes/minutes-....md` 的結果為空）
- [ ] 日期帶著星期，檔名裡的日期和標題裡的日期相同
- [ ] 數字·名字·日期和原始備忘對照過一次（防止價格寫錯這類錯誤）
- [ ] 沒有編造備忘裡沒有的內容
- [ ] 沒有修改 `inbox/` 裡的原件（`git status inbox/` 裡沒有這次工作造成的改動）

**會議紀要**
- [ ] 每條決定的事都寫全了"做什麼·多少/怎麼做·到什麼時候"（沒有的部分寫 `（備忘中沒有）`）
- [ ] 待辦事項表的每一行都有負責人和期限（備忘裡沒有就寫 `（備忘中沒有）` + 也列進第 3 欄）
- [ ] 原始備忘裡的待辦事項全部搬進了表格（原件裡"要做～"的行數 = 表格行數）
- [ ] 寫了下次會議的日期（備忘裡沒有就寫 `（備忘中沒有）`）

最後告訴使用者儲存路徑，以及留成 `（備忘中沒有）` 的欄目列表 — 方便向會議出席者問清楚後補上。

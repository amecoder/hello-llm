# weekly-review — 回顧備忘 → 每週回顧

## 什麼時候用

- 週五（或週末）把那一週的 `inbox/review-YYYY-MM-DD.txt` 備忘彙總，整理成每週回顧的時候
- 例："幫我整理這周（10/27~10/31）的回顧"

## 要讀的檔案（按順序）

1. `CLAUDE.md` — 這個資料夾的 5 條整理規則
2. `templates/README.md` — 模板使用方法和檢查清單
3. `templates/weekly-review.md` — 要用的模板
4. 那一週（週一~週日）日期的原始備忘 `inbox/review-YYYY-MM-DD.txt` **全部** — **只讀取。絕不修改。**
   - 找法：用 `ls inbox/review-*.txt` 看列表，只挑檔名日期在那一週裡的。
   - 請求裡沒說是哪一週的話，就按今天所在的那一週。

## 要用的模板

把 `templates/weekly-review.md` 原樣複製，只填 `{{ }}` 的位置。正文欄目只有 **做得好的 (Keep) → 可惜的 (Problem) → 下週要做的 (Try)** 三個，不改名稱·順序，也不加欄。

各欄的填法：

- **標題** — 那一週的星期一~最後一份備忘的日期。例：`# 每週回顧 — 2026-10-27(週一) ~ 10-31(週五)`
- **原始備忘註釋** — 在標題下面的註釋裡寫上讀過的所有備忘檔案。例：`<!-- 原始備忘：inbox/review-2026-10-29.txt · review-2026-10-30.txt -->`
- **做得好的** — 1~3 條，`做了什麼 — 為什麼做得好`。備忘裡有數字（賣出份數·點贊數）的話，連同日期作為依據補上。
- **可惜的** — 1~3 條，`什麼事 — 為什麼會這樣`。
- **下週要做的** — 1~3 條，`- MM/DD(星期)：行動`。只從備忘裡寫的決心·計劃裡取。
- 備忘裡沒有"為什麼"或日期的話不要編造，在那個位置寫 `（備忘中沒有）`。備忘裡的推測標上 `（備忘裡的推測）`。
- 某一欄在備忘裡找不到可寫的內容時，不要刪欄，寫上 `- （備忘中沒有）`。

日期：正文寫成 `10/29(週三)` 這樣的月/日 + 括號星期。星期要對照日曆確認（`date -j -f %Y-%m-%d 2026-10-29 +%a`）。

**備忘裡沒有的內容不要編造。** 合併幾天的備忘時，不要把數字加起來或改寫，把備忘裡寫的數字連同那天的日期搬過來。

## 儲存位置

- `notes/weekly-review-YYYY-MM-DD.md` — 日期是**那一週的星期一**（不是備忘的日期）
- 例：10/29~10/31 的備忘 → `notes/weekly-review-2026-10-27.md`
- 如果已經有同名檔案，覆蓋之前先問使用者。

## 完成後要核對的檢查清單

重新開啟儲存的檔案，從上往下確認。只要有一項 ✗，就改好後再確認一遍。

**通用**
- [ ] 欄目名稱和順序與模板相同（沒有刪掉的欄 — 沒有可寫的內容就寫 `（備忘中沒有）`）
- [ ] 一個 `{{` 也沒有剩下（`grep -n '{{' notes/weekly-review-....md` 的結果為空）
- [ ] 日期帶著星期，檔名裡的日期（星期一）和標題的開始日期相同
- [ ] 數字·名字·日期和原始備忘對照過一次（防止價格寫成 6,000韓元 這類錯誤）
- [ ] 沒有編造備忘裡沒有的內容
- [ ] 沒有修改 `inbox/` 裡的原件（`git status inbox/` 裡沒有這次工作造成的改動）

**每週回顧 (KPT)**
- [ ] 那一週的回顧備忘一份不漏地讀過，並全部寫進了原始備忘註釋
- [ ] 正文欄目只有做得好的 / 可惜的 / 下週要做的三個，並且是這個順序
- [ ] 三欄都至少寫了 1 條（備忘裡沒有就寫 `（備忘中沒有）`）
- [ ] 做得好的·可惜的都各自寫了"為什麼"（備忘裡沒有就寫 `（備忘中沒有）`）
- [ ] 下週要做的是帶日期的行動，並且至少和一條可惜的事相關聯

最後告訴使用者儲存路徑、讀過的備忘份數，以及留成 `（備忘中沒有）` 的位置 — 方便本人補上"為什麼"。

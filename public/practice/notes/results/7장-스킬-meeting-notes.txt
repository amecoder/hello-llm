# meeting-notes — 회의 메모 → 회의록

## 언제 쓰나

- 회의가 끝나고 `inbox/회의-YYYY-MM-DD-이름.txt` 메모를 회의록으로 정리할 때
- 예: "10/27 주간회의 메모 회의록으로 정리해 줘"

## 읽을 파일 (순서대로)

1. `CLAUDE.md` — 이 폴더의 정리 규칙 5개
2. `templates/README.md` — 양식 사용법과 점검표
3. `templates/회의록.md` — 쓸 양식
4. 원본 메모 `inbox/회의-YYYY-MM-DD-이름.txt` — **읽기만 한다. 절대 고치지 않는다.**

## 쓸 양식

`templates/회의록.md`를 그대로 복사해 `{{ }}` 자리만 채운다. 칸 이름·순서(1. 결정한 것 → 2. 할 일 → 3. 다음에 논의할 것 → 4. 다음 회의)를 바꾸지 않는다.

칸별로 채우는 법:

- **머리말** — 장소·참석·원본 메모 경로. 메모에 없으면 `(메모에 없음)`.
- **1. 결정한 것** — 확정된 것만. 한 줄에 무엇을·얼마/어떻게·언제까지, 핵심은 굵게. 제안자·보류된 안이 메모에 있으면 뒤에 붙인다.
- **2. 할 일** — 메모에서 누가 하기로 한 일을 **전부** 표로 옮긴다. 담당·기한이 메모에 없으면 그 줄을 지우지 말고 `(메모에 없음)`으로 채운 뒤, 같은 일을 3번 칸에도 "담당·기한 미정"으로 올린다. 상태는 `예정` / `진행 중` / `완료(MM/DD)` 셋 중 하나.
- **3. 다음에 논의할 것** — 결론이 안 난 안건, 못 정한 이유, 결정에 필요한 것.
- **4. 다음 회의** — `11/3(월) 오전 10시`처럼. 메모에 없으면 `(메모에 없음)`.
- 쓸 게 없는 칸은 지우지 않고 `(메모에 없음)`이라고 쓴다.

날짜: 제목은 양식대로 `2026-10-27(월)`, 본문은 `10/27(월)`처럼 월/일 + 괄호 요일. 요일은 달력으로 확인한다(`date -j -f %Y-%m-%d 2026-10-27 +%a`).

**메모에 없는 내용은 지어내지 않는다.** 추측이 필요하면 쓰지 말고 `(메모에 없음)`.

## 저장 위치

- `notes/회의록-YYYY-MM-DD-회의이름.md` (날짜는 원본 메모 파일명의 날짜)
- 예: `inbox/회의-2026-10-27-주간회의.txt` → `notes/회의록-2026-10-27-주간회의.md`
- 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 사용자에게 묻는다.

## 끝나고 확인할 점검표

저장한 파일을 다시 열고 위에서부터 확인한다. 하나라도 ✗면 고친 뒤 다시 확인한다.

**공통**
- [ ] 칸 이름과 순서가 양식과 같다 (지운 칸이 없다 — 쓸 게 없으면 `(메모에 없음)`)
- [ ] `{{`가 하나도 남아 있지 않다 (`grep -n '{{' notes/회의록-....md` 결과가 비어 있음)
- [ ] 날짜에 요일이 붙어 있고, 파일명 날짜와 제목 날짜가 같다
- [ ] 숫자·이름·날짜를 원본 메모와 한 번 대조했다 (가격 오기 같은 실수 방지)
- [ ] 메모에 없는 내용을 지어내지 않았다
- [ ] `inbox/` 원본을 고치지 않았다 (`git status inbox/`에 이번 작업으로 생긴 변경이 없음)

**회의록**
- [ ] 결정한 것마다 "무엇을·얼마/어떻게·언제까지"가 다 들어 있다 (없는 부분은 `(메모에 없음)`)
- [ ] 할 일 표의 모든 줄에 담당과 기한이 있다 (메모에 없으면 `(메모에 없음)` + 3번 칸에도 올림)
- [ ] 원본 메모의 할 일이 표에 전부 옮겨졌다 (원본의 "~하기" 줄 수 = 표 줄 수)
- [ ] 다음 회의 날짜가 적혀 있다 (메모에 없으면 `(메모에 없음)`)

마지막으로 사용자에게 저장 경로와, `(메모에 없음)`으로 남긴 칸 목록을 알려 준다 — 회의 참석자에게 물어 채울 수 있게.

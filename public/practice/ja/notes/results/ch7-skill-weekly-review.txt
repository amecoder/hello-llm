# weekly-review — 振り返りメモ → 週間振り返り

## いつ使うか

- 金曜日(または週末)に、その週の`inbox/review-YYYY-MM-DD.txt`のメモを集めて週間振り返りに整理するとき
- 例: 「今週(10/27〜10/31)の振り返りを整理して」

## 読むファイル (順番に)

1. `CLAUDE.md` — このフォルダの整理ルール5つ
2. `templates/README.md` — 様式の使い方とチェックリスト
3. `templates/weekly-review.md` — 使う様式
4. その週(月〜日)の日付の元のメモ `inbox/review-YYYY-MM-DD.txt` **全部** — **読むだけにする。絶対に直さない。**
   - 探し方: `ls inbox/review-*.txt` で一覧を見て、ファイル名の日付がその週に入るものだけを選ぶ。
   - どの週か依頼に書かれていなければ、今日が入っている週にする。

## 使う様式

`templates/weekly-review.md`をそのままコピーして、`{{ }}` の部分だけを埋める。本文の欄は**よかったこと (Keep) → 惜しかったこと (Problem) → 来週やること (Try)** の3つだけで、名前・順番を変えたり欄を足したりしない。

欄ごとの埋め方:

- **タイトル** — その週の月曜日〜最後のメモの日付。例: `# 週間振り返り — 2026-10-27(月) 〜 10-31(金)`
- **元のメモのコメント** — タイトルの下のコメントに、読んだメモのファイルを全部書く。例: `<!-- 元のメモ: inbox/review-2026-10-29.txt · review-2026-10-30.txt -->`
- **よかったこと** — 1〜3個、`何を — なぜうまくいったか`。数字(販売個数・いいねの数)がメモにあれば、日付といっしょに根拠としてつける。
- **惜しかったこと** — 1〜3個、`何が — なぜそうなったか`。
- **来週やること** — 1〜3個、`- MM/DD(曜日): 行動`。メモに書かれた決意・計画からだけ持ってくる。
- 「なぜ」や日付がメモになければ作り上げずに、そこに`（メモになし）`。メモの中の推測は`(メモの推測)`と書く。
- ひとつの欄に入れるものがメモになければ、欄を消さずに`- （メモになし）`と書く。

日付: 本文は`10/29(水)`のように月/日 + かっこの曜日。曜日はカレンダーで確認する(`date -j -f %Y-%m-%d 2026-10-29 +%a`)。

**メモにない内容は作り上げない。** 何日分かのメモをまとめるとき、数字を足したり書き換えたりせず、メモに書かれた数字をその日付といっしょに移す。

## 保存場所

- `notes/weekly-review-YYYY-MM-DD.md` — 日付は**その週の月曜日** (メモの日付ではない)
- 例: 10/29〜10/31のメモ → `notes/weekly-review-2026-10-27.md`
- 同じ名前のファイルがすでにあれば、上書きする前にユーザーに聞く。

## 終わってから確認するチェックリスト

保存したファイルをもう一度開いて、上から確認する。ひとつでも✗なら直してから、もう一度確認する。

**共通**
- [ ] 欄の名前と順番が様式と同じ (消した欄がない — 書くことがなければ`（メモになし）`)
- [ ] `{{`がひとつも残っていない (`grep -n '{{' notes/weekly-review-....md` の結果が空)
- [ ] 日付に曜日がついていて、ファイル名の日付(月曜日)とタイトルの最初の日付が同じ
- [ ] 数字・名前・日付を元のメモと一度照らし合わせた (値段6,000ウォンの書き間違いのようなミスを防ぐ)
- [ ] メモにない内容を作り上げていない
- [ ] `inbox/`の元のメモを直していない (`git status inbox/`に今回の作業でできた変更がない)

**週間振り返り (KPT)**
- [ ] その週の振り返りメモを漏れなく読み、元のメモのコメントに全部書いた
- [ ] 本文の欄がよかったこと / 惜しかったこと / 来週やることの3つだけで、この順番になっている
- [ ] 3つの欄すべてに1つ以上書かれている (メモになければ`（メモになし）`)
- [ ] よかったこと・惜しかったことに、それぞれ「なぜ」がついている (メモになければ`（メモになし）`)
- [ ] 来週やることが日付のある行動で、惜しかったことのうち少なくとも1つとつながっている

最後にユーザーに、保存したパス、読んだメモの数、`（メモになし）`のまま残した部分を伝える — 「なぜ」を本人が埋められるように。

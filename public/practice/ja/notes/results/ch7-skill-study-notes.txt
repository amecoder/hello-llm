# study-notes — 勉強のメモ → 勉強ノート

## いつ使うか

- 講義・本・動画を見て書いた`inbox/study-YYYY-MM-DD-topic.txt`を勉強ノートに整理するとき
- 例: 「10/28のプロンプト講義のメモを勉強ノートにして」

## 読むファイル (順番に)

1. `CLAUDE.md` — このフォルダの整理ルール5つ
2. `templates/README.md` — 様式の使い方とチェックリスト
3. `templates/study-notes.md` — 使う様式
4. 元のメモ `inbox/study-YYYY-MM-DD-topic.txt` — **読むだけにする。絶対に直さない。**

## 使う様式

`templates/study-notes.md`をそのままコピーして、`{{ }}` の部分だけを埋める。欄の名前・順番(1. ひとこと要約 → 2. 要点 → 3. 新しく知った言葉 → 4. 注意すること → 5. 質問すること → 6. やってみること → 7. やってみた結果)を変えない。

欄ごとの埋め方:

- **冒頭** — 出典・分量・元のメモのパス。メモになければ`（メモになし）`。
- **1. ひとこと要約** — メモ全体をひとつの文で。
- **2. 要点** — 3〜7個、メモを写さずにやさしい言葉で書き直す。メモに例があればつける。
- **3. 新しく知った言葉** — メモに出てきた用語と意味を表で。意味がメモになければ作り上げずに意味の欄に`（メモになし）` — この用語は5番の質問することにも載せる。
- **4. 注意すること** — メモに書かれた、間違えやすい点。
- **5. 質問すること** — メモに書かれた、わからないこと・疑問。なければ様式のコメントどおり`(なし)`。
- **6. やってみること** — メモに書かれた実践の計画を`- いつ: 何を`の形で。いつがメモになければ`- （メモになし）: 何を`。
- **7. やってみた結果** — 様式のコメントどおり、最初は`(まだやっていない)`。メモの中にやってみた結果が書かれているときだけ、日付といっしょに埋める。
- 書くことがない欄は消さずに`（メモになし）`と書く。

日付: タイトルは様式どおり`2026-10-28(火)`、本文は`10/28(火)`のように月/日 + かっこの曜日。曜日はカレンダーで確認する(`date -j -f %Y-%m-%d 2026-10-28 +%a`)。

**メモにない内容は作り上げない。** 「自分の言葉で」書き直すのは表現を変えることであって、メモにない知識を足すことではない。

## 保存場所

- `notes/study-YYYY-MM-DD-topic.md` (日付・テーマは元のメモのファイル名から)
- 例: `inbox/study-2026-10-28-prompt-lecture.txt` → `notes/study-2026-10-28-prompt-lecture.md`
- 同じ名前のファイルがすでにあれば、上書きする前にユーザーに聞く。

## 終わってから確認するチェックリスト

保存したファイルをもう一度開いて、上から確認する。ひとつでも✗なら直してから、もう一度確認する。

**共通**
- [ ] 欄の名前と順番が様式と同じ (消した欄がない — 書くことがなければ`（メモになし）`)
- [ ] `{{`がひとつも残っていない (`grep -n '{{' notes/study-....md` の結果が空)
- [ ] 日付に曜日がついていて、ファイル名の日付とタイトルの日付が同じ
- [ ] 数字・名前・日付を元のメモと一度照らし合わせた
- [ ] メモにない内容を作り上げていない
- [ ] `inbox/`の元のメモを直していない (`git status inbox/`に今回の作業でできた変更がない)

**勉強ノート**
- [ ] 要点を写さずにやさしい言葉で書き、3つ以上ある (メモに3つなければ、ある分だけ書いてユーザーに伝える)
- [ ] メモに出てきたわからない言葉は、全部「新しく知った言葉」の表に意味といっしょにある
- [ ] やってみることが「いつ · 何を」できる行動になっている (「上手に書いてみる」✗ → 「月曜日のインスタ投稿に役割+形式を入れる」✓)
- [ ] やってみた結果が`(まだやっていない)`か、メモに書かれた日付・結果になっている

最後にユーザーに、保存したパスと、`（メモになし）`のまま残した欄の一覧を伝える。

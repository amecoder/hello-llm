# meeting-notes — 会議メモ → 議事録

## いつ使うか

- 会議が終わって、`inbox/meeting-YYYY-MM-DD-name.txt` のメモを議事録に整理するとき
- 例: 「10/27の週間会議のメモを議事録に整理して」

## 読むファイル (順番に)

1. `CLAUDE.md` — このフォルダの整理ルール5つ
2. `templates/README.md` — 様式の使い方とチェックリスト
3. `templates/minutes.md` — 使う様式
4. 元のメモ `inbox/meeting-YYYY-MM-DD-name.txt` — **読むだけにする。絶対に直さない。**

## 使う様式

`templates/minutes.md`をそのままコピーして、`{{ }}` の部分だけを埋める。欄の名前・順番(1. 決めたこと → 2. やること → 3. 次に話し合うこと → 4. 次回の会議)を変えない。

欄ごとの埋め方:

- **冒頭** — 場所・出席・元のメモのパス。メモになければ`（メモになし）`。
- **1. 決めたこと** — 確定したことだけ。1行に 何を・いくら/どのように・いつまでに、大事なところは太字で。提案者・保留になった案がメモにあれば、あとに添える。
- **2. やること** — メモで誰かがやることになった仕事を**全部**表に移す。担当・期限がメモになければ、その行を消さずに`（メモになし）`で埋めたうえで、同じ仕事を3番の欄にも「担当・期限未定」として載せる。状態は`予定` / `進行中` / `完了(MM/DD)`の3つのうちひとつ。
- **3. 次に話し合うこと** — 結論が出なかった議題、決められなかった理由、決めるのに必要なもの。
- **4. 次回の会議** — `11/3(月) 午前10時`のように。メモになければ`（メモになし）`。
- 書くことがない欄は消さずに`（メモになし）`と書く。

日付: タイトルは様式どおり`2026-10-27(月)`、本文は`10/27(月)`のように月/日 + かっこの曜日。曜日はカレンダーで確認する(`date -j -f %Y-%m-%d 2026-10-27 +%a`)。

**メモにない内容は作り上げない。** 推測が必要なら書かずに`（メモになし）`。

## 保存場所

- `notes/minutes-YYYY-MM-DD-meeting-name.md` (日付は元のメモのファイル名の日付)
- 例: `inbox/meeting-2026-10-27-weekly.txt` → `notes/minutes-2026-10-27-weekly.md`
- 同じ名前のファイルがすでにあれば、上書きする前にユーザーに聞く。

## 終わってから確認するチェックリスト

保存したファイルをもう一度開いて、上から確認する。ひとつでも✗なら直してから、もう一度確認する。

**共通**
- [ ] 欄の名前と順番が様式と同じ (消した欄がない — 書くことがなければ`（メモになし）`)
- [ ] `{{`がひとつも残っていない (`grep -n '{{' notes/minutes-....md` の結果が空)
- [ ] 日付に曜日がついていて、ファイル名の日付とタイトルの日付が同じ
- [ ] 数字・名前・日付を元のメモと一度照らし合わせた (値段の書き間違いのようなミスを防ぐ)
- [ ] メモにない内容を作り上げていない
- [ ] `inbox/`の元のメモを直していない (`git status inbox/`に今回の作業でできた変更がない)

**議事録**
- [ ] 決めたことごとに「何を・いくら/どのように・いつまでに」が全部入っている (ない部分は`（メモになし）`)
- [ ] やること表のすべての行に担当と期限がある (メモになければ`（メモになし）` + 3番の欄にも載せる)
- [ ] 元のメモのやることが表に全部移されている (元のメモの「〜する」の行数 = 表の行数)
- [ ] 次回の会議の日付が書かれている (メモになければ`（メモになし）`)

最後にユーザーに、保存したパスと、`（メモになし）`のまま残した欄の一覧を伝える — 会議の出席者に聞いて埋められるように。

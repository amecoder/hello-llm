# weekly-review — 回顾备忘 → 每周回顾

## 什么时候用

- 周五（或周末）把那一周的 `inbox/review-YYYY-MM-DD.txt` 备忘汇总，整理成每周回顾的时候
- 例："帮我整理这周（10/27~10/31）的回顾"

## 要读的文件（按顺序）

1. `CLAUDE.md` — 这个文件夹的 5 条整理规则
2. `templates/README.md` — 模板使用方法和检查清单
3. `templates/weekly-review.md` — 要用的模板
4. 那一周（周一~周日）日期的原始备忘 `inbox/review-YYYY-MM-DD.txt` **全部** — **只读取。绝不修改。**
   - 找法：用 `ls inbox/review-*.txt` 看列表，只挑文件名日期在那一周里的。
   - 请求里没说是哪一周的话，就按今天所在的那一周。

## 要用的模板

把 `templates/weekly-review.md` 原样复制，只填 `{{ }}` 的位置。正文栏目只有 **做得好的 (Keep) → 可惜的 (Problem) → 下周要做的 (Try)** 三个，不改名称·顺序，也不加栏。

各栏的填法：

- **标题** — 那一周的星期一~最后一份备忘的日期。例：`# 每周回顾 — 2026-10-27(周一) ~ 10-31(周五)`
- **原始备忘注释** — 在标题下面的注释里写上读过的所有备忘文件。例：`<!-- 原始备忘：inbox/review-2026-10-29.txt · review-2026-10-30.txt -->`
- **做得好的** — 1~3 条，`做了什么 — 为什么做得好`。备忘里有数字（卖出份数·点赞数）的话，连同日期作为依据补上。
- **可惜的** — 1~3 条，`什么事 — 为什么会这样`。
- **下周要做的** — 1~3 条，`- MM/DD(星期)：行动`。只从备忘里写的决心·计划里取。
- 备忘里没有"为什么"或日期的话不要编造，在那个位置写 `（备忘中没有）`。备忘里的推测标上 `（备忘里的推测）`。
- 某一栏在备忘里找不到可写的内容时，不要删栏，写上 `- （备忘中没有）`。

日期：正文写成 `10/29(周三)` 这样的月/日 + 括号星期。星期要对照日历确认（`date -j -f %Y-%m-%d 2026-10-29 +%a`）。

**备忘里没有的内容不要编造。** 合并几天的备忘时，不要把数字加起来或改写，把备忘里写的数字连同那天的日期搬过来。

## 保存位置

- `notes/weekly-review-YYYY-MM-DD.md` — 日期是**那一周的星期一**（不是备忘的日期）
- 例：10/29~10/31 的备忘 → `notes/weekly-review-2026-10-27.md`
- 如果已经有同名文件，覆盖之前先问用户。

## 完成后要核对的检查清单

重新打开保存的文件，从上往下确认。只要有一项 ✗，就改好后再确认一遍。

**通用**
- [ ] 栏目名称和顺序与模板相同（没有删掉的栏 — 没有可写的内容就写 `（备忘中没有）`）
- [ ] 一个 `{{` 也没有剩下（`grep -n '{{' notes/weekly-review-....md` 的结果为空）
- [ ] 日期带着星期，文件名里的日期（星期一）和标题的开始日期相同
- [ ] 数字·名字·日期和原始备忘对照过一次（防止价格写成 6,000韩元 这类错误）
- [ ] 没有编造备忘里没有的内容
- [ ] 没有修改 `inbox/` 里的原件（`git status inbox/` 里没有这次工作造成的改动）

**每周回顾 (KPT)**
- [ ] 那一周的回顾备忘一份不漏地读过，并全部写进了原始备忘注释
- [ ] 正文栏目只有做得好的 / 可惜的 / 下周要做的三个，并且是这个顺序
- [ ] 三栏都至少写了 1 条（备忘里没有就写 `（备忘中没有）`）
- [ ] 做得好的·可惜的都各自写了"为什么"（备忘里没有就写 `（备忘中没有）`）
- [ ] 下周要做的是带日期的行动，并且至少和一条可惜的事相关联

最后告诉用户保存路径、读过的备忘份数，以及留成 `（备忘中没有）` 的位置 — 方便本人补上"为什么"。

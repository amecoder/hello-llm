# study-notes — 学习笔记 → 学习总结

## 什么时候用

- 要把看课程·书·视频时记下的 `inbox/study-YYYY-MM-DD-topic.txt` 整理成学习笔记的时候
- 例："把 10/28 提示词课程的笔记做成学习笔记"

## 要读的文件（按顺序）

1. `CLAUDE.md` — 这个文件夹的 5 条整理规则
2. `templates/README.md` — 模板使用方法和检查清单
3. `templates/study-notes.md` — 要用的模板
4. 原始笔记 `inbox/study-YYYY-MM-DD-topic.txt` — **只读取。绝不修改。**

## 要用的模板

把 `templates/study-notes.md` 原样复制，只填 `{{ }}` 的位置。不改变栏目名称·顺序（1. 一句话总结 → 2. 核心内容 → 3. 新学的词 → 4. 注意事项 → 5. 要提的问题 → 6. 要试的事 → 7. 试过的结果）。

各栏的填法：

- **开头** — 出处·时长·原始备忘路径。备忘里没有就写 `（备忘中没有）`。
- **1. 一句话总结** — 用一句话概括整份笔记。
- **2. 核心内容** — 3~7 条，不要照抄笔记，用简单的话重新写。笔记里有例子就配上。
- **3. 新学的词** — 把笔记里出现的术语和意思做成表格。笔记里没有意思的话不要编造，在意思栏写 `（备忘中没有）` — 这个术语也列进第 5 栏要提的问题。
- **4. 注意事项** — 笔记里写的容易弄错的地方。
- **5. 要提的问题** — 笔记里写的不懂的东西·问号。没有的话按模板注释写 `（没有）`。
- **6. 要试的事** — 把笔记里写的应用计划写成 `- 什么时候：做什么` 的形式。备忘里没有"什么时候"的话写 `- （备忘中没有）：做什么`。
- **7. 试过的结果** — 按模板注释，一开始写 `（还没试过）`。只有笔记里写了试过的结果时，才连同日期填上。
- 没有可写内容的栏不要删，写上 `（备忘中没有）`。

日期：标题按模板写成 `2026-10-28(周二)`，正文写成 `10/28(周二)` 这样的月/日 + 括号星期。星期要对照日历确认（`date -j -f %Y-%m-%d 2026-10-28 +%a`）。

**备忘里没有的内容不要编造。** "用自己的话"重新写只是换个说法，不是补充笔记里没有的知识。

## 保存位置

- `notes/study-YYYY-MM-DD-topic.md`（日期·主题取自原始笔记的文件名）
- 例：`inbox/study-2026-10-28-prompt-lecture.txt` → `notes/study-2026-10-28-prompt-lecture.md`
- 如果已经有同名文件，覆盖之前先问用户。

## 完成后要核对的检查清单

重新打开保存的文件，从上往下确认。只要有一项 ✗，就改好后再确认一遍。

**通用**
- [ ] 栏目名称和顺序与模板相同（没有删掉的栏 — 没有可写的内容就写 `（备忘中没有）`）
- [ ] 一个 `{{` 也没有剩下（`grep -n '{{' notes/study-....md` 的结果为空）
- [ ] 日期带着星期，文件名里的日期和标题里的日期相同
- [ ] 数字·名字·日期和原始笔记对照过一次
- [ ] 没有编造笔记里没有的内容
- [ ] 没有修改 `inbox/` 里的原件（`git status inbox/` 里没有这次工作造成的改动）

**学习笔记**
- [ ] 核心内容没有照抄，是用简单的话写的，有 3 条以上（笔记里不到 3 条的话，有多少写多少，并告诉用户）
- [ ] 笔记里出现的不懂的词全部连同意思放在了「新学的词」表里
- [ ] 要试的事是写明"什么时候 · 做什么"的行动（"好好写写看" ✗ → "周一的 Instagram 文案里加上角色+格式" ✓）
- [ ] 试过的结果是 `（还没试过）`，或者是笔记里写的日期·结果

最后告诉用户保存路径，以及留成 `（备忘中没有）` 的栏目列表。

# meeting-notes — 会议备忘 → 会议纪要

## 什么时候用

- 会议结束后，要把 `inbox/meeting-YYYY-MM-DD-name.txt` 备忘整理成会议纪要的时候
- 例："把 10/27 周会的备忘整理成会议纪要"

## 要读的文件（按顺序）

1. `CLAUDE.md` — 这个文件夹的 5 条整理规则
2. `templates/README.md` — 模板使用方法和检查清单
3. `templates/minutes.md` — 要用的模板
4. 原始备忘 `inbox/meeting-YYYY-MM-DD-name.txt` — **只读取。绝不修改。**

## 要用的模板

把 `templates/minutes.md` 原样复制，只填 `{{ }}` 的位置。不改变栏目名称·顺序（1. 决定的事 → 2. 待办事项 → 3. 下次要讨论的事 → 4. 下次会议）。

各栏的填法：

- **开头** — 地点·出席·原始备忘路径。备忘里没有就写 `（备忘中没有）`。
- **1. 决定的事** — 只写已经确定的事。一行写清做什么·多少/怎么做·到什么时候，重点加粗。备忘里有提议人·暂缓的方案就补在后面。
- **2. 待办事项** — 把备忘里定下由谁来做的事**全部**搬进表格。备忘里没有负责人·期限的话，不要删那一行，填上 `（备忘中没有）`，再把同一件事以"负责人·期限未定"列进第 3 栏。状态是 `预定` / `进行中` / `完成(MM/DD)` 三选一。
- **3. 下次要讨论的事** — 没有结论的议题、没定下来的原因、做决定需要的东西。
- **4. 下次会议** — 像 `11/3(周一) 上午 10 点` 这样写。备忘里没有就写 `（备忘中没有）`。
- 没有可写内容的栏不要删，写上 `（备忘中没有）`。

日期：标题按模板写成 `2026-10-27(周一)`，正文写成 `10/27(周一)` 这样的月/日 + 括号星期。星期要对照日历确认（`date -j -f %Y-%m-%d 2026-10-27 +%a`）。

**备忘里没有的内容不要编造。** 需要推测的话就不写，写 `（备忘中没有）`。

## 保存位置

- `notes/minutes-YYYY-MM-DD-meeting-name.md`（日期用原始备忘文件名里的日期）
- 例：`inbox/meeting-2026-10-27-weekly.txt` → `notes/minutes-2026-10-27-weekly.md`
- 如果已经有同名文件，覆盖之前先问用户。

## 完成后要核对的检查清单

重新打开保存的文件，从上往下确认。只要有一项 ✗，就改好后再确认一遍。

**通用**
- [ ] 栏目名称和顺序与模板相同（没有删掉的栏 — 没有可写的内容就写 `（备忘中没有）`）
- [ ] 一个 `{{` 也没有剩下（`grep -n '{{' notes/minutes-....md` 的结果为空）
- [ ] 日期带着星期，文件名里的日期和标题里的日期相同
- [ ] 数字·名字·日期和原始备忘对照过一次（防止价格写错这类错误）
- [ ] 没有编造备忘里没有的内容
- [ ] 没有修改 `inbox/` 里的原件（`git status inbox/` 里没有这次工作造成的改动）

**会议纪要**
- [ ] 每条决定的事都写全了"做什么·多少/怎么做·到什么时候"（没有的部分写 `（备忘中没有）`）
- [ ] 待办事项表的每一行都有负责人和期限（备忘里没有就写 `（备忘中没有）` + 也列进第 3 栏）
- [ ] 原始备忘里的待办事项全部搬进了表格（原件里"要做～"的行数 = 表格行数）
- [ ] 写了下次会议的日期（备忘里没有就写 `（备忘中没有）`）

最后告诉用户保存路径，以及留成 `（备忘中没有）` 的栏目列表 — 方便向会议出席者问清楚后补上。

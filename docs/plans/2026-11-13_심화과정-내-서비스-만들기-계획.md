# 심화 과정 「내 서비스 만들기」 — 계획 (2026-11-13)

## 결론

1. **4단계(AI-SDLC) 뒤에 별도 심화 과정을 둔다**(2026-11-13 사용자 결정). 4단계는 입문 코스로 그대로 둔다.
2. **독자는 네 트랙이다**(2026-11-13 사용자 결정, 근거 `docs/reports/2026-11-13_심화과정-강의대상자-리서치.md`).

   | 트랙 | 독자 | 만들 것 |
   |---|---|---|
   | 업무 | 총무팀·경리팀 직장인 | 엑셀을 대체하는 업무 도구 |
   | 가게 | 작은 가게·작은 사업 | 예약, 메뉴, 마케팅 등 고객 관리 |
   | 게임 | 취미로 만드는 사람 | 친구들에게 자랑할 게임 |
   | 재테크 | 재테크하려는 사람 | 아주 화려한 데이터 분석 대시보드 |

3. **구성은 「공통 장 + 트랙별 실습」이다**(가정 — 아래 「정할 것」 1). 개념은 장마다 한 번 가르치고, 장 끝 「직접 해 보기」에서 독자가 처음부터 자기 트랙 결과물을 만들어 간다. 남의 예제를 먼저 따라 하지 않는다.
4. **강의를 쓰기 전에 네 트랙 예시 결과물을 실제로 만들어 배포한다.** 만든 기록이 강의의 재료가 되고, 본문의 모든 단계가 실제로 되는지 증명한다(4단계 `cafe-todo-board` 와 같은 방식).
5. **한국어를 먼저 쓰고 번역은 뒤로 미룬다**(터미널 강좌와 같은 방식, 가정).

## 가설·검증 설계

| 항목 | 내용 |
|---|---|
| 가설 | 코딩을 모르는 독자가 이 과정만 읽고 자기 트랙의 결과물을 만들어 인터넷 주소로 공개할 수 있고, 본문의 사실(요금·한도·약관·법)은 확인 날짜의 공식 문서와 어긋나지 않는다 |
| 기준선 | 지금 가이드가 다루는 배포는 GitHub Pages 정적 페이지 하나(4단계 7장)뿐이다. 4단계에서 「백엔드·도메인·롤백·스테이징」은 0회, 「데이터베이스」는 경고로만 2회 나온다(2026-11-13 `grep` 집계). 데이터 저장·로그인·사업용 배포를 따라 할 수 있는 장은 0개다 |
| 판정 기준 | ① 네 트랙 예시 결과물이 모두 공개 주소에서 동작한다(또는 공개하면 안 되는 트랙은 그 이유와 대체 공유 방법을 적는다) ② 예시는 본문 순서대로 만들었고, 본문에 없는 단계를 쓴 곳은 0곳이다(제작 기록과 본문 대조) ③ 공식 자료 리포트의 인용 대조 불일치 0 ④ `npm test`·`npm run docs:build`·`npm run test:e2e` 통과 ⑤ 2026-11-11 초보자 읽기 검사와 같은 채점자·같은 질문으로 각 장을 읽혀 「막힘」 [필수] 0건 ⑥ 쓴 사람과 다른 리뷰어의 리뷰 [필수] 0건 |
| 반증 조건 | 한 트랙이라도 본문만으로 공개까지 가지 못하면 그 트랙은 「완성」이라고 보고하지 않는다 |
| 측정 방법 | 예시 저장소의 커밋 기록·배포 주소 HTTP 200 · 리포트 인용 대조 스크립트 · 읽기 검사 방법은 `docs/reports/2026-11-11_초보자-읽기-검사.md` 「방법」 절 그대로 |

## 장 구성 (가안, 12장)

장 끝 「직접 해 보기」는 네 트랙으로 나눠 쓴다(`### 업무 트랙` 처럼). 독자는 자기 트랙만 읽는다.

| 장 | 제목 | 배우는 것 | 직접 해 보기 결과물 |
|---|---|---|---|
| 1 | 내 서비스 정하기 | 4단계와 무엇이 다른가(진짜 사용자·데이터·돈), 네 트랙, 내 트랙 고르기 | 내 트랙과 한 줄 아이디어 |
| 2 | 아이디어를 설명서로 | AI 인터뷰로 SPEC.md, 「처음 버전」 범위 줄이기 | 트랙별 SPEC.md |
| 3 | 보기 좋은 화면 | 참고 화면 보여 주기, 색·글꼴·움직임 요청, 휴대폰 화면, 화려함과 읽기 쉬움 | 첫 화면(데이터 없이) |
| 4 | 데이터는 어디에 | 파일·스프레드시트·데이터베이스 차이, 트랙별로 무엇을 고르나 | 데이터가 저장되는 화면 |
| 5 | 누가 무엇을 볼 수 있나 | 로그인, 권한, 데이터 접근 규칙(Lovable 사고 사례), 혼자 쓰는 것과 남이 쓰는 것 | 로그인·권한 적용(트랙별 필요한 만큼) |
| 6 | 인터넷에 올리기 | 정적 사이트와 서버가 필요한 사이트, 호스팅 고르기, 사업용 사용 조건, 내 주소(도메인) | 공개 주소 |
| 7 | 진짜처럼 확인하기 | 진짜 같은 데이터로 시험, 휴대폰 확인, 다른 사람에게 써 보게 하기, 증거 받기 | 확인 기록 |
| 8 | 안전과 법 | 비밀값, 개인정보 동의서·처리방침, 통신판매업 신고, 데이터 이용 약관 | 트랙별 점검표 결과(가게: 처리방침) |
| 9 | 고장과 되돌리기 | 백업, 이전 버전으로 되돌리기, 고장 알아채기 | 백업 1회와 되돌리기 1회 |
| 10 | 사람들에게 알리기 | 공유 링크와 미리보기 그림, 가게 홍보 문구·메뉴판, 게임 자랑하기 | 공유용 소개 |
| 11 | 운영과 비용 | 무료 한도 지켜보기, 사용자 의견을 이슈로, 다음 버전 | 의견 1건 반영 |
| 12 | 실습 과제와 다음 걸음 | 처음부터 끝까지 점검표, 트랙을 바꿔 한 번 더, 개발자에게 넘길 때 | 완성 점검표 |

장 번호·폴더(가정): 새 폴더 `guide/40-my-service/`, 메뉴 이름 「5단계 · 내 서비스 만들기」, 장 번호 base 900(1장 = 901). 지금 로드맵의 「4단계가 최종 목표」 문구와 단계 목차·`theme/stages.ts`·사이드바·`guide/index.md`·퀴즈 은행을 함께 고친다.

## 정할 것

1. **구성** — 「공통 장 + 트랙별 실습」으로 가정했다. 대안은 (가) 다 같이 예제 하나를 따라 만든 뒤 갈라지기, (나) 트랙별 독립 코스. 가정한 이유: 독자가 1장부터 자기 결과물을 만들고(리서치에서 사람들의 동기는 「내 것」), 개념은 한 번만 쓰므로 분량이 네 배가 되지 않는다. 위험: 장마다 트랙 실습 네 개를 써야 해서 장 하나가 길어진다.
2. **트랙별 도구** — 리서치(`docs/reports/2026-11-13_심화과정-공식-자료.md`) 뒤 기본값으로 정했다(2026-11-16, 바꿀 수 있음).

   | 트랙 | 호스팅 | 데이터 | 근거 |
   |---|---|---|---|
   | 게임 | GitHub Pages | 없음(점수판은 선택) | 비영리 허용, 4단계에서 배움 |
   | 재테크 | 로컬(내 컴퓨터) | 내 거래 기록 + 출처 밝힌 공공 자료 | 금융위 시세는 제3자 제공·재배포 금지, 내 자산 정보는 공개할 이유가 없다 |
   | 업무 | 구글 Apps Script 웹 앱 | 구글 시트 | 회사 사용자만 접근, 엑셀에서 옮기기 쉬움. 예시는 만들지 않고 가이드만 제공(2026-11-16 사용자 결정) |
   | 가게 | 로컬(사장님 컴퓨터·매장 태블릿) | 내 컴퓨터 안 저장 | 2026-11-16 사용자 결정. 가입 없음, 손님 정보가 인터넷에 나가지 않음 |

   가게 트랙은 손님이 휴대폰으로 여는 예약 페이지가 아니라 **사장님이 매장에서 쓰는 관리 도구**다(전화·방문 예약 받아 적기, 메뉴판 만들기, 손님 명단, 홍보 문구 만들기). Supabase·Cloudflare 가입은 없다.

   업무 트랙은 우리 계정으로 예시를 만들어 배포하지 않는다(2026-11-16 사용자 결정 「그냥 가이드만 제공하자」). 본문은 독자가 자기 구글 계정에서 따라 하는 순서와 Apps Script 공식 문서 근거로 쓰고, 화면 캡처 대신 공식 문서 링크를 단다. 그래서 이 트랙은 판정 기준 ①(동작하는 예시)에서 빠지고, 「실제로 해 보지 않은 단계」라고 본문에 밝힌다.

   판정 기준은 그대로다: 무료로 시작, AI에게 맡겨 설정 가능, 독자가 실제로 써도 약관에 걸리지 않음, 접근 규칙을 화면에서 확인 가능.
3. **업무 트랙의 공개 범위** — 회사 데이터를 외부 서비스에 올리는 것은 회사마다 규칙이 다르다. 예시는 가짜 데이터로 만들고, 본문은 「회사 규칙 먼저 확인」으로 안내한다(가정).
4. **번역 시기** — 한국어 공개 뒤에 정한다.

5. **강의의 범위는 교육이다**(2026-11-16 사용자 결정: "우리는 강좌를 제공하는 거지, 사업을 제공하는 건 아니다"). 예시는 지어낸 가게·지어낸 데이터로 만들고 실제 영업을 하지 않는다. 사업 절차(사업자등록·결제 대행사 계약)는 따라 하지 않고, 8장에 「실제로 영업에 쓰기 전 확인할 것」 점검표(처리방침·광고 문자 동의·통신판매업 신고)로만 안내한다. 단, 독자가 결과물을 실제로 쓸 수 있어야 하므로 도구는 사업용 금지가 없는 것으로 고른다. 가게·재테크는 로컬이라 호스팅 약관이 걸리지 않는다(2026-11-16 사용자 결정 「둘 다 로컬만」). 손님 명단은 로컬이어도 개인정보이므로 8장의 동의·보관·삭제 안내는 남긴다.

## 위험

- 호스팅·데이터베이스 서비스의 무료 한도와 화면은 자주 바뀐다. 장마다 확인 날짜를 적고 리포트에 근거를 둔다.
- 결제(가게 트랙)는 사업자등록·결제 대행사 심사가 필요해 예시로 끝까지 시연할 수 없다. 본문은 「무엇이 필요한지」 지도까지만 다룬다(가정).
- 재테크 트랙은 투자 조언처럼 보이지 않게 쓴다. 본문은 데이터를 보여 주는 법만 다루고, 무엇을 사라는 예시를 쓰지 않는다.
- 업무 트랙은 예시 없이 공식 문서만으로 쓴다. 독자가 막히는 곳을 우리가 미리 겪어 보지 못하므로, 읽기 검사에서 이 트랙의 「막힘」을 따로 센다.

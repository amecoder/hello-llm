# 4단계 AI-SDLC — 가이드 계획 초안 (2026-11-01)

## 사용자 결정 (2026-11-01)

- **"우선은 가이드 목차, 강좌 만들고 그거에 따라서 실습하게"** — 실습 줄기를 먼저 고르지 않는다. SDLC 단계별로 **배울 내용(강좌)으로 목차를 세우고**, 장마다 그 내용을 따라 하는 실습을 붙인다. 아래 「실습 줄기 후보」는 장별 실습 예시를 고를 때의 재료로만 쓴다.
- 순서: 근거 리포트(`docs/reports/2026-11-01_AI-SDLC-공식-자료.md`) → 목차 확정 → 장별 강좌 → 장별 실습.

## 결론 (초안)

1. **목표**: 개발 지식이 없는 독자가 AI와 함께 **작은 소프트웨어 하나를 기획부터 배포·개선까지** 해 본다. SDLC(소프트웨어 개발 전 과정)의 단계마다 "AI에게 무엇을 맡기고, 사람은 무엇을 확인하는가"를 배운다.
2. **추천 실습 줄기**: 3단계 정리도구가 만든 회의록의 **할 일 표를 모아 보여 주는 웹 페이지**(「모퉁이 카페 할 일 보드」)를 만들어 GitHub Pages(무료)로 배포한다. 3단계 결과물을 그대로 입력으로 쓰므로 이야기가 이어지고, 결과를 눈으로 확인할 수 있다.
3. **주 도구는 Claude Code 데스크톱 앱**, 장마다 Codex·Antigravity에서 같은 일을 하는 방법을 한 줄로 덧붙인다(3단계에서 세 도구 모두 다뤘으므로).
4. **장은 12개 안팎.** 1~3단계와 같은 형식(장마다 실습·결과물·확인 질문·퀴즈, 공식 문서 각주, 가설·검증).

## 1. 독자와 전제

| 항목 | 내용 |
|---|---|
| 독자 | 3단계를 마친 비개발자. 폴더·권한·규칙 파일·스킬·Git 기록을 써 봤다 |
| 새로 필요한 것 | GitHub 계정(무료), 웹 브라우저 |
| 다루지 않는 것 | 프로그래밍 문법 강의, 서버·데이터베이스 운영 |
| 비용 | 도구 구독(3단계와 같음) 외 0원 — 배포는 무료 정적 호스팅 |

## 2. 실습 줄기 후보

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 할 일 보드(추천)** | `notes/` 회의록의 할 일 표를 읽어 담당·기한·상태별로 보여 주는 웹 페이지 | 3단계 결과를 그대로 입력으로 씀, 확인 기준이 분명(표의 할 일 수 = 화면의 할 일 수) | 파일 읽기 방식(빌드 때 읽기 vs 붙여 넣기)을 정해야 함 |
| B. 카페 메뉴·공지 사이트 | 메뉴판·공지·영업시간을 보여 주는 소개 사이트 | 가장 쉬움, 결과가 예쁨 | 3단계와 이어지지 않음, 테스트·데이터 개념이 약함 |
| C. 독서 모임 페이지 | 1단계 10장 과제 자료(명단·회비 장부)로 모임 페이지 | 1단계 자료 재사용 | 3단계 실습에서 한 번 기각한 안(2026-10-31) |

## 3. 장별 초안 (A안 기준)

| 장 | 단계 | 배우는 것 | 실습 | 결과물 | 확인 질문 |
|---|---|---|---|---|---|
| 1 | 개요 | SDLC란, AI와 하면 무엇이 바뀌나, 사람이 맡을 일 | 없음 | — | 어느 단계에서 사람이 꼭 확인하나? |
| 2 | 준비 | GitHub 계정·저장소, 로컬 폴더와 연결 | 새 저장소 만들기 | 빈 저장소 | 저장소가 내 계정에 있나? |
| 3 | 기획 | 문제·사용자·하지 않을 것, AI에게 질문받기 | 서연의 불편을 인터뷰 형식으로 정리 | `기획서.md` | 안 만들면 무엇이 불편한가? |
| 4 | 명세 | 요구사항을 확인 가능한 문장으로(스펙 주도 개발 개념) | 기능 5개·확인 기준 | `스펙.md` | 기준마다 예/아니오로 답할 수 있나? |
| 5 | 설계 | 화면 그림·데이터 흐름·작게 나누기 | 화면 스케치와 작업 목록 | 설계 그림, 작업 목록 | 작업 하나가 한 번에 확인 가능한 크기인가? |
| 6 | 구현 | 계획 모드 → 작은 단계 → 커밋, 브랜치 | 할 일 표를 읽어 보여 주는 첫 화면 | 동작하는 페이지 | 메모의 할 일 5개가 화면에 다 있나? |
| 7 | 테스트 | 확인 기준을 자동 테스트로, AI에게 테스트 쓰게 하기 | 할 일 수·기한 형식 테스트 | 테스트 파일, 통과 기록 | 일부러 틀리게 하면 테스트가 실패하나? |
| 8 | 리뷰 | 작성자 ≠ 검토자, 다른 AI로 교차 검토, PR | PR 만들고 검토 의견 반영 | PR, 검토 기록 | 검토가 찾은 문제를 고쳤나? |
| 9 | 배포 | GitHub Pages, 자동 배포, 되돌리기 | 페이지 공개 | 공개 주소 | 휴대폰에서도 열리나? |
| 10 | 운영·개선 | 이슈로 요청 받기, 다음 버전, 회고 | "기한 지난 할 일 빨간색" 개선 | 이슈·두 번째 PR | 고친 뒤에도 기존 테스트가 통과하나? |
| 11 | 안전·책임 | 비밀값·개인정보·라이선스, 공개 저장소 주의 | 공개 전 점검표 | 점검표 | 메모의 실명·연락처가 공개되지 않았나? |
| 12 | 실습 과제·전문가처럼 | 내 문제로 처음부터 | 과제 | 독자의 결과물 | 점검표 전 항목 |

## 4. 근거 조사 계획

- GitHub 공식 문서: 저장소 만들기, GitHub Pages, Actions(자동 배포), 이슈·PR
- 스펙 주도 개발: github/spec-kit, OpenSpec 문서(개념만, 도구 설치는 선택) — `docs/reports/2026-10-20_경쟁-분석.md` 에서 찾은 저장소
- Claude Code 공식 문서(3단계 리포트 재사용): 계획 모드, 커밋·PR, 코드 리뷰 기능
- 리포트 파일: `docs/reports/2026-11-0X_AI-SDLC-공식-자료.md` (VERIFIED 인용만 본문에)

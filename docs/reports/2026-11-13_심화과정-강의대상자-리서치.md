# 심화 과정 강의 대상자 리서치 (2026-11-13)

심화 과정(일반인이 진짜 만들고 싶은 것을 만들어 배포까지 해 보는 과정)을 설계하기 전에, 그 과정의 독자가 누구이고 무엇을 만들려 하며 어디서 막히는지 공개 자료로 확인했다.

## 결론

- **비개발자가 "무엇을 만드는지"를 서비스 모양별 비율로 잰 1차 자료는 없다.** OpenAI·Anthropic·한국 공공 자료 모두 "AI를 무엇에 쓰는가"까지만 잰다.
- 숫자가 있는 유일한 원자료(arXiv 설문, 비개발자 54명)에서는 **취미·창작(59.3%)과 작은 스크립트·자동화(51.9%)가 웹·앱(31.5%)보다 많다.** OpenAI·Anthropic이 든 비개발자 사례도 문서·표·대시보드·내부 도구다.
- **"AI 앱 제작 도구 사용자의 다수는 비개발자"라는 회사 발표는 셋 다 확인했다**(Lovable 80%, Vercel 63%, Replit 58%). 다만 모두 회사가 낸 수치다.
- **가장 많이 기록된 막힘은 보안 — 로그인·데이터베이스 설정 실수다.** Lovable로 만든 앱 170개 이상이 데이터 접근 설정(RLS) 실수로 노출된 사례(CVE-2025-48757)가 대표다. 배포·비용·유지보수가 막힘이라는 수치 자료는 없다.
- 한국에서는 손님 정보를 받으면 동의서·개인정보 처리방침, 온라인으로 팔면 통신판매업 신고(직전 해 50건 미만·간이과세자는 면제)가 따라온다.
- **가설은 판단 보류다.** 미리 정한 기준(VERIFIED 수치 자료 2개 이상)을 채우는 자료가 없다. 있는 근거는 가설의 반대 방향(혼자·회사 안에서 쓰는 도구가 더 많다)으로 기운다.

## 가설과 판정 기준 (조사 전에 정함)

| 항목 | 내용 |
|---|---|
| 가설 | 비개발자가 AI로 만들려는 것 중 가장 큰 덩어리는 로그인·데이터 저장이 있는 웹 서비스이고, 결제와 휴대폰 앱은 그보다 적다 |
| 채택 | 출처가 확인된(VERIFIED) 자료 2개 이상에서 웹 서비스·웹 앱 비중이 가장 크다 |
| 기각 | 내부 업무 도구나 휴대폰 앱이 더 크게 나온다 |
| 보류 | 판정할 자료가 1개 이하 |

**판정: 보류(반대 방향으로 기움).** 비율을 잰 VERIFIED 자료는 arXiv 설문 하나다. 거기서 웹·앱(31.5%)은 취미·창작과 스크립트·자동화보다 적다. 다만 이 설문의 "웹·앱"은 로그인 여부를 나누지 않고, 표본이 54명이며, 앱 제작 도구 사용자가 아니라 주로 ChatGPT로 코드를 만든 사람이다. 결제·휴대폰 앱 비율은 어느 자료에도 없다.

## 방법

- 자료 묶음 4개를 하위 에이전트 4개가 나눠 조사했다: Anthropic, OpenAI, 비개발자용 AI 앱 제작 도구(Lovable·Replit·Bolt·v0 등), 한국 공공 자료.
- 별도 사실 대조 에이전트가 핵심 주장 15개를 원문에서 다시 확인했다. 웹 읽기 도구는 작은 모델이 요약해 주므로, 대조는 `curl`로 원문을 받고 PDF는 `pdftotext`로 읽어 글자 그대로 찾았다. 결과: 14개 확인, 1개 일부 다름(아래 「주의」).
- 한계: agy(Gemini) 검색 한도로 일부 에이전트는 검색 없이 주소를 짐작해 찾았다. 빠진 자료가 있을 수 있다. openai.com 블로그는 접속이 막혀(403) PDF 논문만 원문으로 읽었다.

- **서울 소상공인 300곳 중 AI 사용 9.7%, AI 도입 걸림돌 비용 69.0%**: 신문 칼럼 인용(2차 자료). 원 보고서를 열지 못했다.

## 질문별 정리

### 1. 무엇을 만들려 하나

- 비율 자료는 arXiv 설문(C4) 하나다: 취미·창작과 작은 자동화가 웹·앱보다 많고, 업무에 실제로 쓰는 것은 16.7%다.
- 회사 자료는 비율 없이 예를 든다. Lovable은 웹사이트·내부 도구·CRM(고객 관리)·재고 관리·인사 시스템·쇼핑몰을 든다(C1 블로그). OpenAI는 문서·표·대시보드·내부 도구(C8), Anthropic은 사내 도구와 자동화(C10·C11)를 든다.
- 결제는 Lovable이 2026년 2월에야 기능을 열었고(C1), 비율 자료는 없다. 휴대폰 앱 비율 자료도 없다.

### 2. 어디서 막히나

- **보안(로그인·데이터베이스)**: 실제 사고(C6), 걱정 72.3%(C5), "어떻게 지켜야 하는지 모른다"(C2). 비개발자는 AI 코드를 확인하지 않는 유일한 집단이다(C4).
- **오류 고리**: arXiv 설문의 비개발자는 "디버깅 대신 다시 프롬프트하기", 코드가 깨져 포기하기에 모두 중간값 4(5점 척도)로 답했다(C4, 비율은 없음).
- **배포**: Replit 전 임원 인터뷰는 "실제로 무언가를 배포하게 만드는 것"이 이용자를 붙잡는 고비라고 했다(Sacra, 2025-08-30, 의견이지 데이터가 아님).
- **비용·유지보수**: 수치 자료 없음.
- **한국 규칙**: 개인정보 동의서·처리방침(C14), 통신판매업 신고(C15). 사업자등록·결제 대행사(PG) 심사는 공식 출처를 찾지 못했다.

### 3. 누구인가

- 앱 제작 도구 사용자의 다수가 비개발자라는 회사 발표(C1·C2·C3). Lovable은 빠르게 느는 집단으로 창업자·디자이너·영업직을 든다.
- 동기: 절반 이상이 사업, 4분의 1이 돈 벌 부업(Lovable 설문, C1). arXiv 설문 비개발자는 취미 64.8%, 개인 프로젝트 55.6%, 업무 27.8%(C4).
- 나이: 앱 제작 도구 사용자의 나이 자료는 없다. arXiv 설문 전체 표본은 25~44세가 71.6%다.
- 한국: 생성형 AI 경험률 44.5%(C12). 소상공인은 디지털 기술을 27.2%가 쓰고, 주로 온라인 판매와 매장 관리다(C13). 60대 이상은 "이용 방법을 몰라서" 안 쓴다는 답이 상대적으로 많다(언론 기사).

## 페르소나 (근거에서 만든 가상 인물)

각 인물은 위 근거를 묶어 만든 것이다. 비율로 인물의 크기를 정할 자료는 없다.

### A. 회사 일을 줄이고 싶은 직장인

- 예: 35세 총무팀 대리. 매주 엑셀 세 개를 합쳐 보고서를 만든다.
- 만들고 싶은 것: 표를 합쳐 주는 도구, 팀 대시보드, 사내 신청서.
- 근거: C8(Codex 지식 노동자), C10·C11(Anthropic 비기술 직원), C4(자동화 51.9%), Lovable 내부 도구 예시.
- 막힐 곳: 회사 데이터를 어디까지 넣어도 되는지, 동료와 공유하는 방법(로그인·권한).

### B. 내 가게나 작은 사업을 하려는 사람

- 예: 42세 꽃집 사장. 전화와 메신저로 예약을 받다가 지쳤다.
- 만들고 싶은 것: 예약 페이지, 손님 명단, 작은 온라인 판매.
- 근거: C1(절반 이상 사업, 창업자), C5(창업자 36.4%), C13(소상공인 온라인 판로 49.0%).
- 막힐 곳: 손님 정보 저장과 보안(C6·C14), 결제와 통신판매업 신고(C15), 운영비.

### C. 취미로 만들어 보고 싶은 사람

- 예: 28세 대학원생. 보드게임 모임 점수판을 만들고 싶다.
- 만들고 싶은 것: 게임, 개인 기록, 모임용 작은 페이지.
- 근거: C4(취미·창작 59.3%, 개인 프로젝트 55.6%), C7(업무 외 사용 70% 이상), Codex 개인 사용자(C8).
- 막힐 곳: 오류가 나면 다시 묻기만 반복하는 고리(C4), 친구에게 보여 줄 배포.

### (참고) D. 부업으로 돈을 벌고 싶은 사람

- Lovable 설문의 "돈 벌고 싶은 부업" 4분의 1(C1)에서 나온 인물이다. 회사 설문 하나뿐이라 근거가 약하다. B와 겹치는 막힘(결제·신고·보안)이 많다.

## 사용자가 정한 페르소나와 만들 것 (2026-11-13)

리서치의 A~D를 사용자가 구체적인 결과물로 바꿔 정했다. 재테크 인물이 새로 들어왔다.

| 인물 | 만들 것 | 리서치 근거 |
|---|---|---|
| 총무팀·경리팀 직장인 | 엑셀을 대체하는 업무 도구 | A (C4 자동화, C8, C10·C11) |
| 내 가게·작은 사업 | 예약, 메뉴, 마케팅 등 고객 관리 | B (C1, C5, C13~C15) |
| 취미로 만드는 사람 | 게임 — 동기는 사람들에게 보여 주고 인기를 얻는 것 | C (C4 취미·창작) |
| 재테크하려는 사람 | 데이터 분석 대시보드 — 화면이 아주 화려해야 함 | 새 인물. C4의 데이터 분석·시각화 31.5%, C10의 data science 12.7% 외에는 이번 리서치에 직접 근거가 없다 |

## 과정 설계에 주는 시사점 (결정은 아님)

- 세 인물 모두 **데이터를 다루는 순간 보안이 첫 고비**다. 로그인과 데이터베이스를 넣는다면, 데이터 접근 설정 확인을 과정의 필수 단계로 둘 근거가 있다(C6).
- 인물마다 "배포"의 뜻이 다르다. A는 회사 안 공유, B는 손님에게 공개, C는 친구에게 링크다.
- B를 끝까지 데려가면 한국 법(개인정보·통신판매)이 과정 안으로 들어온다.
- 결제와 휴대폰 앱은 수요를 잴 자료가 없다.

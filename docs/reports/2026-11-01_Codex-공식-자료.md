# Codex 공식 자료 사실 확인 (2026-11-01)

## 이 문서의 용도

- 3단계 `guide/21-codex/`(장 번호 base 500, 계획: `docs/plans/2026-11-01_Codex-실습-커리큘럼.md`)를 쓸 때 근거로 쓰는 **사실 확인 리포트**다. 본문에는 이 문서에서 **VERIFIED** 로 표시한 값만 옮긴다.
- 독자는 Claude Code 장에서 `CLAUDE.md`·스킬 3개가 든 「정리도구」 폴더를 만든 **비개발자**다. 그래서 이 리포트는 "Claude Code에서 해 본 것이 Codex에서는 어떻게 다른가"에 맞춰 사실을 골랐다.
- **확인 방법**: 공식 문서 사이트 learn.chatgpt.com 의 마크다운 원문(`https://learn.chatgpt.com/docs/<slug>.md`)을 2026-11-01 에 내려받아 읽었다. 52개 페이지 + 합본 매뉴얼(`codex-manual.md`, 3MB)에서 장별로 필요한 문장만 뽑았다. 추가로 `mobile`·`web`·`security-administration`·`reference/slash-commands` 4개를 같은 날 내려받았다. `guides/best-practices` 는 404 로 받지 못했다. 인용 241개(항목 173개)는 내려받은 원문과 공백만 맞춰 대조해 모두 일치함을 확인했다(불일치 0, 대조 스크립트는 작업 폴더에만 두고 저장소에 넣지 않음).
- **표기 약속**
  - 항목 번호 `장-번호`(예: 3-06). 각 항목은 한국어 설명 → 상태 → 출처 URL → 영어 원문 인용 순서다.
  - 상태: **VERIFIED** = 원문에서 직접 읽음 / **충돌** = 문서끼리 다름 / **UNVERIFIED** = 문서에서 찾지 못함(「확인 못 한 것」 절로 모았다)
  - 인용은 원문 그대로다. 마크다운 강조(`**`)·링크·백틱도 원문대로 두었고, 줄바꿈만 공백 하나로 합쳤다.
  - 합본 매뉴얼에서 찾은 문장은 그 절의 원래 페이지(`Source:` 줄) URL 을 적었다.
  - 확인일은 모두 2026-11-01.
- **주의 1 — 문서의 주어가 "ChatGPT"다.** Codex가 ChatGPT 데스크톱 앱 안으로 들어오면서 문서 대부분이 "ChatGPT can…"으로 쓴다. Codex 화면 이야기인지 ChatGPT Work 이야기인지는 문장마다 표면(app·cli·ide·web) 표시를 보고 골랐다.
- **주의 2 — 문서 상당수가 터미널(CLI) 기준이다.** 특히 권한 기본값·`/permissions`·`/import` 는 CLI 설명이 더 자세하다. 앱에서도 같은지는 **화면으로 확인**한다.
- **주의 3 — 한국어 화면 이름은 영어 문서로 알 수 없다.** 메뉴 이름은 영어 그대로 적었다. 본문에 쓰기 전에 캡처로 확정한다.

## 결론 — 가이드에 꼭 반영할 것

1. **Codex는 ChatGPT 데스크톱 앱 안에서 고르는 모드다.** 앱 하나를 설치하고, 위쪽 선택 메뉴에서 ChatGPT(그 안에서 Chat·Work)와 Codex를 고른다(1-02, 2-05). Codex는 diff(바뀐 내용) 같은 개발자용 정보를 보여 주고, Work는 기술 정보를 숨기고 완성된 결과물 위주로 보여 준다(1-07, 1-08).
2. **Work와 Codex는 사용량을 같이 쓴다.** 요금·크레딧·한도가 공유된다(1-10). 무료·Go 플랜은 데스크톱 앱에서 가벼운 모델(GPT-6 Luna)만, 그것도 "점진적 제공(rollout)"이다(8-01, 8-02).
3. **규칙 파일은 `AGENTS.md`다. `CLAUDE.md` 는 읽지 않는다.** 목록에 없는 파일 이름은 무시한다(3-09). 앱의 **가져오기(Import)** 가 Claude Code의 규칙 파일·스킬·설정·슬래시 명령을 옮겨 주지만, 원래 설정은 그대로 두고 복사만 한다(3-12~3-18). 가져온 뒤 권한·훅·인자가 있는 명령은 꼭 검토하라고 한다(3-17).
4. **Git이 아닌 폴더는 불리하다.** 바뀐 내용 보기(review pane)는 Git 저장소가 있어야 열리고, 없으면 앱이 만들자고 한다(2-15). 워크트리도 Git 전용이다(4-21). CLI 문서는 Git이 아닌 폴더에 **읽기 전용**을 권장한다(4-12). 「정리도구」 폴더는 실습 초반에 Git 저장소로 만들게 안내하는 편이 낫다(필자 판단).
5. **권한은 세 가지 이름으로 보인다.** Ask for approval(작업 폴더 안은 스스로, 밖으로 나갈 때 묻기, 기본 추천)·Approve for me(그 질문을 사람 대신 검토 에이전트가 판단)·Full access(제한 없음)(4-02~4-08). Approve for me도 작업 범위를 넓히지 않는다(4-06). 기본적으로 인터넷은 꺼져 있다(4-10).
6. **되돌리기는 Git으로 한다.** 앱의 리뷰 창에서 덩어리(hunk)·파일·전체 단위로 되돌릴 수 있다(4-14, 4-15). 그런데 리뷰 창은 Codex가 고친 것뿐 아니라 **내가 고친 것까지** 보여 주므로 "전체 되돌리기"는 내 변경도 지운다(4-16). Claude Code의 체크포인트(되감기)에 해당하는 기능은 문서에서 **찾지 못했다**(확인 못 한 것 #3).
7. **스킬 폴더 위치가 다르다.** Codex는 `.agents/skills`(프로젝트)와 `$HOME/.agents/skills`(개인)를 읽는다(5-09, 5-10). 부를 때는 Codex에서 `$이름`, ChatGPT에서 `@이름`이다(5-04). 작업 폴더 안의 `.agents`·`.codex` 폴더는 기본 권한에서 **읽기 전용으로 보호**된다(4-13). 스킬을 고쳐 달라고 하면 승인을 물을 수 있다(화면 확인).
8. **예약 작업은 앱에서만 만든다.** 내 컴퓨터 파일을 쓰는 예약은 컴퓨터가 켜져 있고 앱이 실행 중이어야 한다(6-02). CLI에는 예약 관리 화면이 없다(6-04). 예약은 사람 없이 돌며 기본 권한 설정을 따른다(6-10~6-12).
9. **클라우드는 GitHub 저장소와 "게시된 환경"이 전제다.** 내 컴퓨터의 파일·로그인 상태는 클라우드로 넘어가지 않는다(2-08, 6-14~6-16). 휴대폰은 클라우드 또는 연결된 내 컴퓨터를 조종하는 리모컨이다(6-18~6-21).
10. **터미널 `codex exec` 는 기본이 읽기 전용이다.** 대화형 `codex` 와 기본값이 다르다(7-06). `/permissions`·`/import` 는 CLI 명령이고, 앱의 슬래시 명령 목록에는 없다(7-10, 7-12, 확인 못 한 것 #6).
11. **안전**: 프롬프트 인젝션(문서 속 숨은 지시) 경고가 여러 곳에 있다(8-15~8-17). GPT-6 Astra는 안전 감시가 작업을 멈출 수 있고, CLI·모바일에서는 멈추면 작업이 끝난다(8-18~8-20). 개인 플랜의 학습 사용 여부 설정은 이 문서들에 없다(확인 못 한 것 #9).

**4-05** 메뉴에 들어갈 수 있는 것: **Ask for approval**, **Approve for me**, **Full access**, 이름 붙은 사용자 프로필. — VERIFIED · https://learn.chatgpt.com/docs/sandboxing · 확인일 2026-11-01
> "Depending on your configuration, the menu can include **Ask for approval**, **Approve for me** for eligible approval requests, **Full access**, and named or custom permissions profiles."

**4-06** 승인을 누가 하는지 바꿔도 샌드박스(울타리)는 넓어지지 않는다. Approve for me도 Ask for approval과 같은 경계를 쓰고, 경계를 넘는 요청만 자동 검토로 보낸다. — VERIFIED · https://learn.chatgpt.com/docs/permission-modes · 확인일 2026-11-01
> "Changing who reviews a request doesn't expand the sandbox."

**4-07** Full access는 평소의 샌드박스 제한 없이 도는 모드다. 설정으로는 "샌드박스 없음 + 승인 묻지 않음" 조합이다. — VERIFIED · https://learn.chatgpt.com/docs/glossary , https://learn.chatgpt.com/docs/sandboxing · 확인일 2026-11-01
> "Mode where Codex runs without normal sandbox restrictions."
> "Full access means using `sandbox_mode = "danger-full-access"` together with `approval_policy = "never"`."

**4-08** 제한 없는 모드는 파일·네트워크 경계를 모두 없애므로, 정말 전부 맡기고 싶을 때만 쓰라고 한다. — VERIFIED · https://learn.chatgpt.com/docs/sandboxing · 확인일 2026-11-01
> "This removes the filesystem and network boundaries and should be used only when you want the agent to act with full access."

**4-09** 자동 검토(Approve for me의 바탕)는 모델을 한 번 더 부르므로 사용량이 늘 수 있다. — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "Automatic review uses extra model calls, so it can add to Codex usage."

## 4.2 샌드박스와 승인

**4-10** 기본적으로 인터넷이 꺼진 채 돈다. 내 컴퓨터에서는 운영체제가 강제하는 샌드박스가 보통 작업 폴더로 범위를 묶는다. — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "By default, the agent runs with network access turned off."

**4-11** 기본 조합(Auto 프리셋)에서는 작업 폴더 안에서 읽기·고치기·명령 실행을 하고, 폴더 밖 수정이나 인터넷 접근은 승인이 필요하다(CLI 표). — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "Codex can read files, make edits, and run commands in the workspace. Codex requires approval to edit outside the workspace or to access network."

**4-12** Git 폴더면 Auto(작업 폴더 쓰기 + 필요할 때 묻기), Git이 아닌 폴더면 **읽기 전용**을 권한다. 이 절은 CLI 명령 예시와 함께 있어 앱에서도 같은지는 화면 확인이 필요하다. — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "On launch, Codex detects whether the folder is version-controlled and recommends:"
> "Non-version-controlled folders: `read-only`"

**4-13** **보호 폴더**: 기본 쓰기 모드에서도 작업 폴더 안의 `.git`·`.agents`·`.codex` 는 읽기 전용이고, 그 아래 전부가 보호된다. 5장에서 `.agents/skills` 를 만들거나 고칠 때 승인을 물을 수 있다(필자 추론, 화면 확인). — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "`<writable_root>/.agents` is protected as read-only when it exists as a directory."
> "`<writable_root>/.codex` is protected as read-only when it exists as a directory."
> "Protection is recursive, so everything under those paths is read-only."

## 4.3 되돌리기 — Git으로

**4-14** 앱 안에서 덩어리(chunk)별·파일별로 확정(stage)하거나 되돌리고(revert), 커밋·푸시·PR까지 할 수 있다. — VERIFIED · https://learn.chatgpt.com/docs/environments/local-environment · 확인일 2026-11-01

**4-15** 전체·파일·덩어리 세 단위가 있다. 일부만 받아들이려면 확정(staging), 버리려면 되돌리기(revert). — VERIFIED · https://learn.chatgpt.com/docs/code-review · 확인일 2026-11-01
> "**Entire diff**: Use the action buttons in the review header, such as **Stage all** or **Revert all**."
> "Use staging when you want to accept part of the work, and revert when you want to discard it."

**4-16** **주의**: 리뷰 창에는 Codex의 변경뿐 아니라 내가 직접 고친 것, 커밋 안 된 다른 변경도 모두 들어 있다. 그래서 **Revert all** 은 내 변경까지 지울 수 있다(필자 추론). — VERIFIED · https://learn.chatgpt.com/docs/code-review · 확인일 2026-11-01
> "It includes changes made by Codex, changes you made yourself, and any other uncommitted changes in the repository."

**4-17** 작업 전후로 Git 체크포인트(커밋)를 만들어 두라고 CLI·IDE 문서가 권한다. Codex 문서가 말하는 "체크포인트"는 Claude Code의 자동 체크포인트가 아니라 **내가 만드는 Git 커밋**이다. — VERIFIED · https://learn.chatgpt.com/docs/codex/cli · 확인일 2026-11-01
> "Create Git checkpoints before and after a task so you can revert changes."

**4-18** 맡기기 전에 `git status` 를 깨끗이 하고, 자주 커밋해 조금씩 되돌릴 수 있게 하라. — VERIFIED · https://learn.chatgpt.com/docs/agent-approvals-security · 확인일 2026-11-01
> "Work on a feature branch and keep `git status` clean before delegating."
> "Commit frequently so you can roll back in small increments."

**4-19** 단축키 표에 "마지막 앱 동작 되돌리기(⌘+Z)"가 있다. 이것이 Codex의 파일 수정까지 되돌리는지는 문서에 없다 → 확인 못 한 것 #3. — VERIFIED(단축키 존재만) · https://learn.chatgpt.com/docs/reference/commands · 확인일 2026-11-01
> "| Undo last app action | **⌘+Z** |"

**4-20** 고치기 전에 계획부터: 앱 입력창에서 `/plan` 을 쓰면 조사하고 방법을 제안한 뒤에 고친다. Claude Code의 Plan 모드 자리다. — VERIFIED · https://learn.chatgpt.com/docs/prompting · 확인일 2026-11-01
> "For a multi-step task, enter `/plan` in the app composer when you want Codex to investigate and propose an approach before editing."

# 5장 근거 — 스킬과 플러그인

## 5.1 스킬이란

**5-01** 스킬은 특정 일이나 작업 흐름에 필요한 지침과 자료를 묶은 것이다. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "A **skill** packages instructions and supporting resources for a specific task or workflow."

**5-02** 스킬은 `SKILL.md` 가 든 폴더이고, `SKILL.md` 에는 `name` 과 `description` 이 꼭 있어야 한다. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "A skill is a directory with a `SKILL.md` file plus optional scripts and references. The `SKILL.md` file must include `name` and `description`."

**5-03** 스킬은 공개 표준(agent skills)을 따른다. Claude Code 스킬과 같은 형식이라 그대로 옮기기 쉽다는 근거다(형식 동일성은 필자 판단). — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "Skills build on the [open agent skills standard](https://agentskills.io)."

**5-04** 직접 부를 때 ChatGPT는 `@`, Codex는 `$` 를 쓴다. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "ChatGPT supports `@` mentions, while Codex supports `$` mentions for skills."

**5-05** 앱 입력창에서 `$` 를 쳐서 스킬을 부를 수 있고, 켜진 스킬은 슬래시 명령 목록에도 나온다. — VERIFIED · https://learn.chatgpt.com/docs/reference/slash-commands · 확인일 2026-11-01
> "You can also explicitly invoke skills by typing `$` in the chat composer."
> "Enabled skills also appear in the slash command list."

**5-06** 부르지 않아도, 요청이 스킬 `description` 과 맞으면 알아서 고를 수 있다(암묵 호출). — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "**Implicit invocation:** ChatGPT or Codex can choose a skill when your task matches the skill `description`."

**5-07** 그래서 설명(description)에 주된 용도와 신호 단어를 앞쪽에 쓴다. 설명이 잘려도 맞출 수 있게. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "Front-load the key use case and trigger words so a host can still match the skill if descriptions are shortened."

**5-08** 자동 호출을 막으려면 `agents/openai.yaml` 에서 끈다. 끄더라도 `$이름` 으로는 부를 수 있다. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "`allow_implicit_invocation` (default: `true`): When `false`, Codex won't implicitly invoke the skill based on user prompt; explicit `$skill` invocation still works."

## 5.2 스킬 폴더 위치

**5-09** 저장소 안에서는 지금 폴더부터 저장소 맨 위까지 모든 폴더의 `.agents/skills` 를 훑는다. Claude Code의 `.claude/skills` 는 위치 표에 없다. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "For repositories, Codex scans `.agents/skills` in every directory from your current working directory up to the repository root."

**5-10** 위치 표(원문 칸). 프로젝트용 = 지금 폴더의 `.agents/skills`, 개인용 = `$HOME/.agents/skills`(모든 폴더에서 씀), 기본 제공 = skill-creator 등. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "`$CWD/.agents/skills` <br /> Current working directory: where you launch Codex."
> "`$HOME/.agents/skills` <br /> Any skills checked into the user's personal folder."
> "Useful skills relevant to a broad audience such as the skill-creator and plan skills."

**5-11** 심볼릭 링크(바로가기)로 된 스킬 폴더도 따라간다. `.claude/skills` 를 링크로 연결하는 방법도 가능하다는 근거(필자 판단, 본문에서는 복사를 권장). — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "Codex supports symlinked skill folders and follows the symlink target when scanning these locations."

**5-12** 따로 쓰는 스킬은 데스크톱 앱·CLI·IDE에서 된다. 웹·모바일에서는 플러그인에 들어 있는 스킬만 쓴다. — VERIFIED · https://learn.chatgpt.com/docs/build-skills · 확인일 2026-11-01
> "Standalone skills are available in the ChatGPT desktop app, Codex CLI, and IDE extension."

## 5.3 스킬 만들기

**5-13** 만드는 도우미: ChatGPT는 `@skill-creator`, Codex는 `$skill-creator`. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "In ChatGPT, start with `@skill-creator`; in Codex, use `$skill-creator`."

**5-14** 좋은 첫 스킬 예: 주간 보고, 회의 후속 정리처럼 단계와 형식이 늘 같은 일. 「정리도구」의 주간 회고와 맞는다. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "Good first skills include a weekly update, a campaign brief, a meeting follow-up, or any task where the steps and format should stay consistent."

## 5.4 플러그인

**5-15** 플러그인은 스킬과 MCP 서버(외부 도구 연결)를 담을 수 있는 설치 꾸러미다. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "A **plugin** is an installable bundle that can include skills and Model Context Protocol (MCP) servers."

**5-16** ChatGPT와 Codex는 플러그인 목록 하나를 같이 쓴다. 앱에서는 **Plugins** 탭에서 찾고 설치한다. IDE 확장은 플러그인을 지원하지 않는다. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins , https://learn.chatgpt.com/docs/plugins · 확인일 2026-11-01
> "ChatGPT and Codex share one universal plugin directory."
> "Open the **Plugins** tab to browse and install plugins."
> "The IDE extension doesn't support plugins."

**5-17** 고르는 기준: 정해진 일의 지침이면 스킬, 외부 서비스 연결까지 묶어 설치할 거면 플러그인. — VERIFIED · https://learn.chatgpt.com/docs/skills-and-plugins · 확인일 2026-11-01
> "Use a skill when you need reusable instructions for a focused task."

**5-18** 플러그인의 훅(자동 실행 스크립트)은 돌기 전에 검토하고 믿을 만한지 판단하라. — VERIFIED · https://learn.chatgpt.com/docs/plugins · 확인일 2026-11-01
> "Review and trust plugin hooks before they run."

# 6장 근거 — 예약·클라우드·휴대폰

## 6.1 예약 작업(Scheduled tasks)

**6-01** 반복 작업을 예약해 뒤에서 돌린다. 진행·일시정지·완료된 작업은 **Scheduled** 에서 본다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Schedule recurring tasks to run in the background."

**6-02** 데스크톱 앱 예약은 로컬 프로젝트를 쓸 수 있다. 내 파일이 필요하면 컴퓨터를 켜 두고 앱을 실행해 둬야 한다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "In the ChatGPT desktop app, scheduled tasks can work with local projects and run in the project directory or an isolated worktree. Keep the computer on and the app running when a scheduled task needs local files."

**6-03** Git이 아닌 폴더에서는 예약이 폴더 안에서 바로 돈다(워크트리로 분리 불가). — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "In non-version-controlled projects, scheduled tasks run directly in the project directory."

**6-04** CLI에는 예약 관리 화면이 없다. 웹이나 데스크톱 앱에서 만든다. IDE 확장도 같다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Codex CLI doesn't provide the Scheduled management interface."

**6-05** 웹 예약은 업로드한 자료와 연결 도구는 쓰지만, 내 컴퓨터 폴더에서는 일할 수 없다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Web tasks can use uploaded context and connected tools, but they can't work directly in a folder on your computer."

**6-06** 예약 목록과 실행 기록은 앱 사이드바의 **Scheduled** 에 있다. 결과가 있는 실행이 모이는 받은편지함 역할이다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Find all scheduled tasks and their runs on **Scheduled** in the ChatGPT desktop app sidebar."
> "The **Scheduled** view acts as your inbox."

**6-07** 두 종류. 단독 예약은 실행마다 새 대화를 시작하고, 대화 안 예약은 그 대화로 돌아와 기존 맥락을 쓴다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Standalone scheduled tasks start a new chat for each scheduled run and report results in **Scheduled**."
> "Schedule a task inside an existing chat when you want ChatGPT to return to that chat on a schedule."

**6-08** 대화로 예약을 만들고 고칠 수 있다("매주 금요일 오후 5시에…"). — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "You can create and update scheduled tasks from a ChatGPT or Codex chat."

**6-09** 예약 프롬프트에서 `$스킬이름` 으로 스킬을 직접 부를 수 있다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "In the ChatGPT desktop app, you can explicitly trigger a skill in a scheduled task prompt by using `$skill-name`."

**6-10** 예약은 사람 없이 돌고 기본 샌드박스 설정을 쓴다. 조직이 막지 않으면 승인을 묻지 않는(`never`) 방식으로 돈다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "Scheduled tasks run unattended with your default sandbox settings."
> "Scheduled tasks use `approval_policy = "never"` when your organization policy allows it."

**6-11** 기본이 읽기 전용이면 파일을 고쳐야 하는 예약은 실패한다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "If your sandbox mode is **read-only**, tool calls fail if they require modifying files, accessing network, or working with apps on your computer."

**6-12** 기본이 Full access면 예약은 묻지 않고 파일을 바꾸고 명령을 돌리고 인터넷에 나갈 수 있어 위험이 크다. — VERIFIED · https://learn.chatgpt.com/docs/automations · 확인일 2026-11-01
> "If your sandbox mode is **full access**, background scheduled tasks carry elevated risk, as ChatGPT may change files, run commands, and access network without asking."

**6-13** 자리를 비워도 로컬 대화가 이어지게 macOS·Linux에서 **Prevent sleep while running** 을 켤 수 있다. — VERIFIED · https://learn.chatgpt.com/docs/reference/settings · 확인일 2026-11-01
> "On macOS and Linux, turn on **Prevent sleep while running** so local chats can continue while you step away."

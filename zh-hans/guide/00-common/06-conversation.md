# 第6章 在对话中不断打磨

> **一句话总结**：AI 的第一次回答不是成品，而是初稿。在同一个对话里边改边完善；
> 一旦对话开始变乱，就带着摘要换到新对话里。

## AI 能记住多少对话

### 在同一个对话里，它记得

在同一个对话窗口里来回说过的内容，AI 回答时都会一起读。所以你说"把刚才那篇文章的第二段缩短一点"，
它就知道你指的是哪篇文章。

准确地说，AI 并不是把对话"存起来"。更像是**每次回答时，都把整段对话从头重新读一遍**。
想一想[第1章](01-what-is-llm.md)讲过的**上下文窗口**（一次能读进去的文字量）。对话还在这个范围内的时候，AI 才能参考前面的内容。

这样来回多次的对话叫作**多轮**（multi-turn）对话。**一轮**（turn）就是你说一次、AI 答一次。

### 在新对话里，默认它不知道

打开一个新的对话窗口时，AI 对之前的对话一无所知。昨天花了很久讲清楚的情况，今天要重新告诉它。

有些服务有**记忆**（memory）功能，会记住之前对话的一部分。
不同服务的行为和设置方法不一样，我们放到第2阶段（各服务指南）再讲。
这一章里，请先按"新对话从零开始"来用。

## 怎样把修改要求说清楚

回答不合心意时，最常见的错误是这样说：

```
不怎么样。重写。
```

AI 不知道哪里不怎么样，所以只会给你一篇水平差不多的另一篇文章。要求修改时，请加上三样东西。

| 要素 | 问题 | 例子 |
|---|---|---|
| **改哪里** | 哪个部分有问题？ | "第三句""结论部分""整体语气" |
| **怎么改** | 想改成什么样？ | "更短一点""加上数字""别那么生硬" |
| **哪些不动** | 必须保留什么？ | "第一段很好，保持原样" |

加上这三样，就变成下面这样。和"不怎么样"不同，要改的地方和要保留的地方都很清楚。

```
整体思路不错。第三段太长了，帮我缩成两句话。
最后一句的"谢谢"保持不变，其余语气保持现在这样。
```

### 可以直接用的修改说法

| 遇到这种情况 | 可以这样说 |
|---|---|
| 太长了 | "只留下核心，缩短到一半长度" |
| 太生硬了 | "改成像关系好的前辈跟后辈说话那样" |
| 太老套了 | "去掉谁都会说的话，改成只适用于这个情况的内容" |
| 看不懂 | "这部分请举个例子，让初中生也能听懂，再解释一遍" |
| 想知道依据 | "告诉我你这样想的三个理由" |
| 忘了最初的指示 | "请重新遵守我一开始说的条件（五句话以内，用敬语）" |

### 指示照做了却没用时——说出目标

你说"再短一点"，它真的变短了。可是重要的内容也一起被删掉了。
这是 AI 守住了你话里的字面，却没抓住你的意思。

这时候把同一句话说得更用力，通常也改不好。换个办法，加上**你为了什么这样要求**。[^academy-goal]

**不够好的例子**

```
再短一点。真的要很短。
```

**更好的例子**

```
再短一点。目标是让忙碌的组长能读到最后，
并且记住第二段里的调查结果。
```

区别在最后一行。知道了目标，AI 才能判断该留什么、删什么。

"三行以内""做成表格"说的是形式，"让团队相信这个日程"说的才是目标（见[第4章「好提示词的5个要素」](04-prompt-basics.md#好提示词的5个要素)）。
发出请求之前，先问问自己：我只说了形式，还是也说了目标？

## 重新生成、修改提问、接着追问——什么时候用哪个

大多数服务都有三种方法可以重新得到回答。按钮的名称和位置因服务而异，第2阶段会配合画面一起演示。

| 方法 | 做什么 | 适合什么时候 |
|---|---|---|
| **接着追问** | 在当前回答的基础上，请它修改 | 方向对了，只需改一部分时 |
| **重新生成** | 用同一个问题再得到另一个回答 | 问题没问题，只是这次回答碰巧不理想时 |
| **修改我的提问** | 把我发出的问题改一改再发一次 | 第一次提问漏了信息时 |

为什么对同一个问题按"重新生成"会得到不同的回答？就像[第1章](01-what-is-llm.md)讲的，AI 在挑"下一个词"的时候，
是从最合理的候选里**按概率**挑的。所以同一个问题，每次的回答都会有一点不同。

### 再点一次之前——先弄清楚问题出在哪

回答不对劲时，很容易先点"重新生成"。在那之前，先看看这是哪一类失败。知道失败的类型，就能直接用对应的办法。[^academy-diagnose]

- **名字、数字、出处看起来很像真的，但让人怀疑** → 回到原始资料去核对（[第9章](09-safety.md#核对的四个习惯)）。
- **在长对话里忘了最初的条件** → 重新告诉它条件，或者带着交接备忘录换到新对话（见下面的[「什么时候开始新对话」](#什么时候开始新对话)）。
- **计算错了** → 如果服务能用代码来计算，就请它这样做。
- **无条件同意我的想法** → 告诉它可以提出反对意见（[第1章](01-what-is-llm.md#_5-容易附和我的话——谄媚)）。

如上表所示，重新生成适合"问题没问题，只是回答碰巧不理想"的情况。如果原因另有所在，就先解决那个原因，而不是再点一次。

## 什么时候开始新对话

一个对话拖得太久，回答反而会变差。因为前面聊过的内容会一直影响后面。
比如在同一个对话里，先花很久做了店铺宣传文案，再请它写简历，简历里就可能混进宣传文案的口气。

![回答不满意时：方向对，就指出要改的地方请它修改；方向错了，而且对话很长或话题变了，就让它写摘要并开始新对话，否则把请求重写一遍，在同一个对话里再试](../../../guide/00-common/assets/ch6-decide.svg)

看到下面这些信号，就开始新对话吧。

- **话题变了** —— 比如从规划旅行转到公司报告时
- **开始忘记最初的指示** —— 总是违反一开始定好的语气或篇幅时
- **重复同样的错误** —— 请它改了，类似的错误还是不断出现时
- **对话变得非常长** —— 要往上翻很久才能看到开头时

## 换到新对话的方法——摘要交接

开始新对话，并不意味着要丢掉目前为止定下来的东西。请**在原来的对话里让它写一份摘要，再贴到新对话里。**
这和公司里换负责人时写的工作交接备忘录是一回事。

**在原来的对话里**

```
我想在新对话里接着做这件事。请按下面的项目写一份交接备忘录。
- 目标：正在做什么
- 已确定的内容：到目前为止定下的内容和条件
- 我的偏好：我说过喜欢的和不喜欢的
- 剩下的事：接下来要做的事
```

**在新对话里**

```
下面是我在之前的对话里整理的交接备忘录。请根据这些内容，从"剩下的事"的第一项开始接着做。

---
[粘贴交接备忘录]
---
```

请用[第5章](05-prompt-patterns.md)讲的**分隔符**（`---`）把备忘录括起来。这样 AI 就不会把备忘录的内容和我的请求混在一起。

## 把好用的提示词存起来

改了好几次才得到好结果的请求，别扔掉，收集到记事本里。下次遇到类似的事，只要换掉空格里的内容就能再用。

```
[整理周报用]
下面是我这周的工作笔记。请整理成要汇报给组长的周报。
做成"已完成 / 进行中 / 下周计划"三栏的表格，每一项写一行。

---
[本周笔记]
---
```

像这样留出空格、可以反复使用的请求，叫作**提示词模板**（prompt template）。
有些服务还有功能，可以把这类指示存起来，每次自动应用。这个也放到第2阶段再讲。

## 动手试试

1. 在新对话里，只请求"推荐一下下周五团队聚餐的地方"。
2. 对得到的回答，加上**修改3要素**（改哪里、怎么改、哪些不动），请它修改两次。
3. 让它写一份交接备忘录，贴到**新对话**里，接着说"按这些条件，帮我写一条预订咨询短信"。

看看新对话的回答，问问自己：前面定好的人数、预算、地区这些条件，都保持住了吗？

## 总结

- 在同一个对话里，AI 会一起读前面的内容；新对话则从零开始。
- 提修改要求时，要说清"改哪里、怎么改、哪些不动"。
- 话题变了，或者 AI 开始忘记最初的指示，就让它写交接备忘录，换到新对话。
- 好用的请求存成模板，反复使用。

## 术语整理

| 术语 | 中文名称 | 一句话解释 |
|---|---|---|
| Multi-turn | 多轮对话 | 来回多次的对话 |
| Turn | 轮 | 问一次、答一次的一个回合 |
| Context Window | 上下文窗口 | AI 一次能读进去的文字量（[第1章](01-what-is-llm.md)） |
| Memory | 记忆 | 记住之前对话一部分内容的服务功能 |
| Regenerate | 重新生成 | 用同一个问题得到另一个回答 |
| Prompt Template | 提示词模板 | 只换空格内容就能反复使用的请求框架 |
